设备名单

20-secrets.sh 顺便建了 /etc/sing-box/devices.list，第一台叫 main。服务端的 users 数组就是从它渲染的，所以改名单 → 重跑 30 就生效。

# 名字 凭据 平台 —— 一台设备一行
main   af2358a4-df32-419c-9774-63a44c540970  desktop
phone  9b2c1d70-3e44-4a1b-8c02-7e5d9f10a333  android

一台设备一个凭据，同时当 VLESS 的 uuid 和 Hysteria2 的 password 用——所以删一行就是吊销那台，两条入口同时失效，不会漏一边。名单建议纳入 git。

改凭据请用 device.sh，别手改名单：它会顺手重渲染服务端并重新生成那台的客户端配置。

常用

DRY_RUN=1 bash 30-render-server.sh   # 只生成配置，不动系统
systemctl status sing-box
journalctl -u sing-box -n 50 --no-pager
systemctl restart sing-box

设备管理

device.sh 在服务器上就地完成：改名单 → 重渲染服务端 → 重新生成那台的客户端 JSON，然后你把 JSON 拿去分发。它不自己实现任何 sing-box 逻辑，渲染一律走现有脚本，所以不会和模板漂移。

sudo bash device.sh list
sudo bash device.sh add laptop [desktop|android|ios]   # 默认 desktop
sudo bash device.sh rotate laptop                       # 换凭据，旧配置立刻失效
sudo bash device.sh revoke laptop                       # 删掉，两条入口同时失效
sudo bash device.sh render laptop                       # 只重渲染客户端配置

产物在 /etc/sing-box/clients/sing-box-client-<名字>-<平台>.json：

scp root@服务器:/etc/sing-box/clients/sing-box-client-laptop-desktop.json laptop@机器:~/
每台设备只发它自己那一份。整个 devices.list 落到任何一台机器上，就等于把所有设备的凭据都给了它。名单本身也要进 .gitignore 或单独加密存放。
add / rotate / revoke 都会重启 sing-box。当前活跃会话不会断（连接已建立），但新连接会短暂受影响。
