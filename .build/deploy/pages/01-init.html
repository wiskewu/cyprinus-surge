1 · 系统初始化

登录并上传脚本

ssh root@你的服务器IP

# 在你自己电脑上执行（不是服务器）
scp -r docs/deploy/scripts root@你的服务器IP:/root/deploy

运行初始化

cd /root/deploy
bash 00-bootstrap.sh

# SSH 不是 22 端口时：
SSH_PORT=你的端口 bash 00-bootstrap.sh

它会装依赖、开 BBR、加 1G swap、开时间同步、把 SSH 收成仅公钥登录，并把防火墙收成「只放行 SSH 端口、443/tcp、8443-8447/udp」。幂等，可以重复跑。

SSH 加固的一处细节

脚本会写 /etc/ssh/sshd_config.d/99-proxy.conf 关闭密码登录，但 Ubuntu 镜像自带一个 50-cloud-init.conf，里面写着 PasswordAuthentication yes——而 sshd 对每个关键字取第一个出现的值，50 排在 99 前面，会赢。所以脚本同时会就地改掉那个文件（原文件备份为 .orig）。改完用 sshd -t 验证，通过才重启；不通过就回滚本步改动。

没有公钥就不会关密码。脚本先检查 authorized_keys，没有就跳过加固并提示你——先 ssh-copy-id 装好公钥，再重跑这一步。否则一台还没配过密钥的机器会被直接锁死。

确认

systemd-detect-virt                 # kvm
test -c /dev/net/tun && echo TUN-OK # TUN-OK
sysctl net.ipv4.tcp_congestion_control   # bbr
sshd -T | grep -i '^passwordauthentication'   # passwordauthentication no
ufw status                          # 里面有你的 SSH 端口和 443

还有第二层防火墙：云厂商安全组

ufw 只是里层。云厂商控制台里的安全组 / 云防火墙是外层，脚本碰不到。典型症状：443 通但 8443 超时，或者反过来——同一个服务不同端口表现不一致。这时不是配置错，是外层还没放行。

在服务商控制台里，把下面这几个端口手工加进出站规则（协议必须对）：

端口协议谁用
你的 SSH 端口（默认 22）TCP你自己登录用
443TCPREALITY 主入口
8443–8447UDPHysteria2 备入口 + 端口跳跃（ENABLE_HY2=0 时用不到）

以后再改端口（比如给 REALITY 换高位端口），两层都要改，否则就是上面那个症状。

或者干脆让 SSH 走 fwknop。把公网 22 端口彻底关掉、靠单包授权敲门进来，SSH 加固手册覆盖了整套做法。那之后安全组里就不用留 SSH 端口了。
