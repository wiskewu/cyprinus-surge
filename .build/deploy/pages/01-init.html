1 · 系统初始化

登录并上传脚本

ssh root@你的服务器IP

# 在你自己电脑上执行（不是服务器）
scp -r docs/deploy/scripts root@你的服务器IP:/root/deploy

运行初始化

cd /root/deploy
bash 00-bootstrap.sh

# SSH 不是 22 端口时：
SSH_PORT=你的端口 bash 00-bootstrap.sh

SSH_PORT 是「额外放行」，不是「只放行」：脚本会自己探测 sshd 的真实端口（当前连接 → ss 监听 → ssh.socket → sshd_config），探测到的一律放行。但从云控制台 / VNC 登录（没有 SSH_CONNECTION）或 socket 激活的 sshd 又拿不到监听信息时，防火墙就只按 SSH_PORT 开——填错就是把自己关在门外。日志里会出现「探测不到 sshd 在听哪个端口」的警告，看到就先核实：

ss -tlnp | grep -E 'sshd|:22'        # 实际监听（socket 激活时看 systemctl cat ssh.socket）
sshd -T | grep -i '^port'

它会装依赖、开 BBR、加 1G swap、开时间同步、把 SSH 收成仅公钥登录，并把防火墙收成「只放行 SSH 端口、443/tcp、8443-8447/udp」。幂等，可以重复跑。

SSH 加固的三处细节

脚本会写 /etc/ssh/sshd_config.d/99-proxy.conf 关闭密码登录，但 sshd 对每个关键字只取「第一个出现的值」，所以 drop-in 不一定算数：

  • Ubuntu 镜像自带 50-cloud-init.conf 里写着 PasswordAuthentication yes，50 排在 99 前面 → 它赢。脚本会就地改掉这个文件（原文件备份为 .orig）。
  • 有些镜像（含部分云厂商自定义镜像）的 sshd_config 根本没有 Include sshd_config.d，那 drop-in 就是一整个死文件，密码登录字面没变。脚本会补一条 Include /etc/ssh/sshd_config.d/*.conf 到文件最顶部（备份 sshd_config.before-include），sshd -t 不过就回滚。
  • 两种都处理完还不行，脚本不再一句「请手工确认」了之，而是把当前生效值和谁设的这个关键字列出来（排除自己的 .orig 备份），照着改靠前那个。

上一轮报过 [!] 未生效：/etc/ssh/sshd_config 里可能没有 Include sshd_config.d 的，就是上面第二条——把脚本重新 scp 上去重跑即可；想手工补也就一行：

grep -qiE '^[[:space:]]*Include[[:space:]]' /etc/ssh/sshd_config || \
  sed -i '1i Include /etc/ssh/sshd_config.d/*.conf' /etc/ssh/sshd_config
sshd -t && systemctl restart ssh && sshd -T | grep -i '^passwordauthentication'
没有公钥就不会关密码。脚本先检查 authorized_keys，没有就跳过加固并提示你——先 ssh-copy-id 装好公钥，再重跑这一步。否则一台还没配过密钥的机器会被直接锁死。

被跳过 SSH 加固了？三步补上（不是死循环）

跳过的含意就是密码登录还开着，所以你现在进得来，装公钥也进得来。整套动作从你自己的电脑开始：

# 1) 把本机公钥装到服务器（端口换成你的实际端口）
ssh-copy-id -p 你的SSH端口 root@服务器IP

# 2) 另开一个新会话验证：只允许公钥也得能进
ssh -o PreferredAuthentications=publickey -o PasswordAuthentication=no -p 你的SSH端口 root@服务器IP true && echo 公钥OK

# 3) 回服务器重跑本步
cd /root/deploy && SSH_PORT=你的SSH端口 bash 00-bootstrap.sh

看到 [+] 已生效：passwordauthentication no 就成了，可用 sshd -T | grep -i '^passwordauthentication' 复核。不要先手动关密码登录再跑脚本——那才是真死循环。

只能用云控制台（本地没有 ssh 客户端）时，把公钥贴进去也一样管用：

mkdir -p ~/.ssh && chmod 700 ~/.ssh
echo 'ssh-ed25519 AAAAC3Nza... 你备注' >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys

要把 SSH 挪到非 22 端口（可选）

脚本不会改 sshd 的端口，只会放行。挪端口一律「先开新、再关旧」：

# 1) 两层都先放行新端口：ufw + 云厂商安全组
ufw allow 4061/tcp

# 2) 改 sshd（没有 Port 行就追加到末尾）
sed -i 's/^#*Port .*/Port 4061/' /etc/ssh/sshd_config
grep -qi '^Port' /etc/ssh/sshd_config || echo 'Port 4061' >>/etc/ssh/sshd_config
sshd -t && systemctl restart ssh

# sshd 由 socket 激活时（systemctl cat ssh.socket 有 ListenStream=22）还要改 socket：
#   mkdir -p /etc/systemd/system/ssh.socket.d
#   printf '[Socket]\nListenStream=\nListenStream=4061\n' > /etc/systemd/system/ssh.socket.d/override.conf
#   systemctl daemon-reload && systemctl restart ssh.socket

# 3) 另开一个终端确认能进（当前会话先别关）
ssh -p 4061 root@服务器IP

# 4) 确认无误再关旧端口：ufw delete allow 22/tcp，安全组里删 22
已经把自己挡在外面了？从云控制台 VNC / 串口进去 ufw allow 你的端口/tcp（应急可先 ufw disable），具体见排查手册的「SSH 端口连不上」。

确认

systemd-detect-virt                 # kvm
test -c /dev/net/tun && echo TUN-OK # TUN-OK
sysctl net.ipv4.tcp_congestion_control   # bbr
sshd -T | grep -i '^passwordauthentication'   # passwordauthentication no
ss -tlnp | grep -E 'sshd|:22'       # sshd 真实在听哪个端口
ufw status                          # 里面有你的 SSH 端口和 443，端口对得上上面那条

还有第二层防火墙：云厂商安全组

ufw 只是里层。云厂商控制台里的安全组 / 云防火墙是外层，脚本碰不到。典型症状：443 通但 8443 超时，或者反过来——同一个服务不同端口表现不一致。这时不是配置错，是外层还没放行。

在服务商控制台里，把下面这几个端口手工加进出站规则（协议必须对）：

端口协议谁用
你的 SSH 端口（默认 22）TCP你自己登录用
443TCPREALITY 主入口
8443–8447UDPHysteria2 备入口 + 端口跳跃（ENABLE_HY2=0 时用不到）

以后再改端口（比如给 REALITY 换高位端口），两层都要改，否则就是上面那个症状。

或者干脆让 SSH 走 fwknop。把公网 22 端口彻底关掉、靠单包授权敲门进来，SSH 加固手册覆盖了整套做法。那之后安全组里就不用留 SSH 端口了。
