2 · 多客户端密钥

一台设备一把密钥，删一行就是吊销那台，其余不受影响。

两种模式

每设备独立 推荐全部共用 简单
生成命令--clients "laptop phone"--shared
吊销一台删一个 stanza，其余不受影响全换，所有设备重配
密钥泄露影响面一台所有设备

代价只是多一个密钥包文件，脚本已经替你做了。

为什么可以靠密钥区分设备

access.conf 支持多个 stanza，服务端收到包后逐个试解密，只有对上的那个能开规则（server/incoming_spa.c 的 incoming_spa()）。所以所有 stanza 都写 SOURCE ANY，客户端会换 IP，靠地址区分在漫游时直接失效。

参数与命名

参数含义落到哪里
--hosts "server1=1.2.3.4"这批密钥管哪几台服务器：名字=地址，空格分隔可写多台名字 → ~/.fwknoprc 的 [server1] stanza 名 + ~/.ssh/config 的 Host server1；地址 → 敲门的 SPA_SERVER 与 HostName
--clients "laptop phone"每台客户端各一对独立密钥clients/<名字>.env 一份；服务端包里一行 CLIENTS="laptop=… phone=…"，在 access.conf 里各成一个 stanza
--shared所有客户端共用一对（与 --clients 二选一）仍生成 clients/shared.env；吊销只能全换
--out FILE服务端包路径，默认 spa-keys.env客户端的包总落在同目录的 clients/
--split FILE不生成新密钥，从已有服务端包拆出客户端包写入 clients/<名字>.env；见下文
--clients-dir DIR拆分输出的目录，默认 clients只对 --split 生效

名字只允许 [A-Za-z0-9._-]：它会进 grep、fwknop 的 stanza 名和 ssh config 的 Host。hosts 里的名字起短一点，以后你要敲的就是 ssh server1、fwknop -n server1。多台服务器用同一份密钥就够：客户端拿到 HOSTS 里每台一个 stanza，每台服务器自己渲染自己的 access.conf。

和部署手册的 devices.list 没有关系

两套凭据、两套吊销，互不影响，分属不同层，「能不能进门」和「进门后能不能上网」：

哪一套管什么名字从哪来吊销怎么做
devices.list
（部署手册第 3 页）		sing-box 的代理凭据（VLESS uuid / Hysteria2 password）device.sh add mac desktopdevice.sh revoke mac
--clients
（本手册）		SSH 敲门用的 fwknop 密钥生成密钥时手写从密钥包删掉那台，重跑 10-server.sh

名字不必一致，数量也不必一致（一台只用来代理、从不 SSH 的平板，就不必写进 --clients）。建议还是用同一套叫法，出问题时「这台是哪台」一眼能对上。

密钥包

服务端那份（不要发给任何一台客户端）：

SPA_PORT=62201
SSH_PORT=22
ACCESS_TIMEOUT=120
MAX_FW_TIMEOUT=300
HMAC_DIGEST_TYPE=SHA512
HOSTS="server1=203.0.113.10 server2=198.51.100.7"
CLIENTS="laptop=<KEY>:<HMAC> phone=<KEY>:<HMAC>"

每台客户端那份只含自己，其余字段与上面相同：

HMAC_DIGEST_TYPE=SHA512
HOSTS="server1=203.0.113.10 server2=198.51.100.7"
CLIENT_NAME=laptop
CLIENTS="laptop=<KEY>:<HMAC>"

sshd 监听多个端口时（比如刚挪端口那阵 22 与 4061 并存），写回的值是一整串、必须带引号：

SSH_PORT="22 4061"           # 不带引号的话，source 时会把 4061 当命令执行
ACCESS tcp/22,tcp/4061      # 客户端 ~/.fwknoprc 里的写法（逗号分隔）
OPEN_PORTS tcp/22,tcp/4061; # 服务端 access.conf 里的写法（也是逗号）
格式坑：每客户端的键值必须写在一行带引号的 CLIENTS="..." 里。写成 CLIENT laptop=... 不是合法 shell 赋值，脚本 source 这个文件时会直接报 CLIENT: command not found。

只有服务端包时，怎么拿回客户端包

常见情形：换机器时 clients/ 丢了，服务端那份 spa-keys.env 还在。密钥是同一对，不需要重新生成，直接拆：

# 在服务端跑，与 spa-keys.env 同目录
bash 00-gen-keys.sh --split spa-keys.env
bash 00-gen-keys.sh --split spa-keys.env --clients-dir /root/clients   # 指定输出目录

ls clients/
# laptop.env  phone.env

拆出来的是拷贝：SPA_PORT、SSH_PORT、ACCESS_TIMEOUT、MAX_FW_TIMEOUT、HOSTS 原样带过去，再按名字补 CLIENT_NAME 与该设备那一行 CLIENTS。密钥不变，服务端 access.conf 不用重跑，拿着新包直接跑 20-client.sh 即可。

源文件里的 SHARED=… 也能拆，输出为 clients/shared.env。重复跑安全：目标文件内容与源一致时跳过，不一致才改写。

不要用 --clients 重新生成来补客户端包。那会换掉全部密钥，得重跑 10-server.sh、逐台重配，手上还在用的设备会全部敲门失败。--force 同效，不是修丢失，是轮换。

渲染出的 access.conf

# --- laptop ---
SOURCE ANY;
OPEN_PORTS tcp/22;
FW_ACCESS_TIMEOUT 120;
MAX_FW_TIMEOUT 300;
HMAC_DIGEST_TYPE SHA512;
KEY_BASE64        <laptop 的密钥>;
HMAC_KEY_BASE64   <laptop 的 HMAC 密钥>;

多端口时 OPEN_PORTS 是逗号列表：OPEN_PORTS tcp/22,tcp/4061;，与客户端 ACCESS 一一对应。

字段含义
OPEN_PORTS收到有效包后开哪些端口，服务端说了算
FW_ACCESS_TIMEOUT规则保留多少秒（不设默认 30）
MAX_FW_TIMEOUT封顶，客户端 --fw-timeout 也拿不到超过这个值（不设默认 300）
HMAC_DIGEST_TYPEHMAC 摘要算法，必须与客户端 ~/.fwknoprc 的取值相同。stanza 不写这一项时 fwknopd 固定按 SHA256 校验，客户端声明 SHA512 就永久报 Non-corresponding HMAC，密钥全对也一样

没开 PERMIT_CLIENT_PORTS，所以客户端在 ACCESS 里写什么都改变不了服务端放行的端口。脚本渲染后会自检：stanza 数必须等于密钥组数，对不上就退出。

吊销与轮换

# 吊销一台：从密钥包去掉那台，重跑服务端
sudo bash 10-server.sh --keys spa-keys.env

# 全量轮换：--force 重新生成，分发新包，逐台重跑
bash 00-gen-keys.sh --hosts "..." --clients "laptop phone" --force

两套 stanza 可以共存，所以能先加新的、确认都迁走了再删旧的。吊销后顺手把设备上那份密钥包删掉，服务端拒绝对它只是「连不上」，本地文件仍是有效凭据。
