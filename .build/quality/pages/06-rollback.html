6 · 卸载与回退

不想用了、换机器了、把自己卡在门外了——退回公网直连，脚本负责顺序，你只需要回答几个问题。

退出（回到不敲门的直连）

用 90-uninstall.sh，不要手敲 iptables。登录方式、密钥包去留、是否真的拆，都会逐条问，不替你选默认值：

# 服务器：先放行公网 SSH 并回读确认，再停 fwknopd、清跳转、关 SPA 端口、还原配置
sudo bash 90-uninstall.sh              # 交互式，推荐
sudo bash 90-uninstall.sh --check      # 只看现状，什么都不改

# 非交互（脚本、heredoc）：关键步骤必须显式给，缺了就退出
sudo bash 90-uninstall.sh --password no -y                         # 仅公钥
sudo bash 90-uninstall.sh --password yes --root-login yes -y       # 密码登录，root 也能用密码
sudo bash 90-uninstall.sh --password no --purge -y                 # 连 access.conf 与密钥包一起删

# 每台客户端：还原 ~/.fwknoprc，摘掉 ~/.ssh/config 里的托管块
bash 90-uninstall.sh --client
bash 90-uninstall.sh --client --purge --keys ~/laptop.env   # 连本地那份密钥包一起删
顺序是安全的关键。收口之后公网 SSH 规则已经不存在，唯一在放行的是 FWKNOP_INPUT 里那条临时规则。90-uninstall.sh 因此先 ufw allow 并回读确认，确认不了就直接退出（此时 SPA 还完整）——绝不在「SSH 没路可走」的状态下先拆 SPA。
参数作用不给会怎样
--password yes|no退出后是否允许密码登录；no 时连 KbdInteractiveAuthentication 一起关（键盘交互式也能送密码）交互式会问；非交互直接退出
--root-login yes|no|prohibit-password只影响 root：prohibit-password = 只允许公钥登 root--password yes 且 root 当前是 prohibit-password 时，非交互直接退出（否则只开密码登录等于没解决）
-y, --yes跳过拆除确认交互式会问；非交互直接退出
--purge连 access.conf 与密钥包一起删交互式会问；默认保留

改的是实际生效的那一行：sshd 对每个关键字只取「第一个出现的值」，而 Include sshd_config.d 会按文件名顺序就地展开。所以 50-cloud-init.conf 里若写着 PasswordAuthentication no，脚本改的就是它，而不是自己那份 99-*.conf。改完 sshd -t 校验、reload，并用 sshd -T 回读确认——对不上就把「谁设的」列出来。

开密码登录＝回到可被爆破的状态。只在你需要换回旧方式、或机器上没有可用公钥时才开；开着就让 fail2ban 继续跑（fail2ban-client status sshd）。只想恢复访问的话，更稳的做法是把新公钥装进 authorized_keys，密码登录保持 no。

还原之后的状态：公网 SSH 直连、不再需要敲门、fwknopd 停用、fwknopd.conf 用回包自带那份。fail2ban 与代理配置不动；客户端的 ~/.ssh/config 里只删带 # BEGIN ssh-spa 标记的那一段，你自己的配置原样保留。

选「仅公钥」而本机又没找到 authorized_keys 时，脚本会在拆之前警告：拆完只剩云控制台能进。

拆除输出的四行怎么读

脚本收尾会打印四行。其中两行不是陈述，是交回给你的待办：一行要回读确认，一行要转发到每台客户端。说已开启密码登录的那一行，需要实际跑一次才算验收。

确认 fail2ban 在运行

拆掉 SPA 又打开密码登录，SSH 端口重新对全网开放，爆破尝试就是常态。fail2ban 读 sshd 写下的认证失败记录，同一个 IP 在窗口内失败到阈值就写 iptables 封禁，这是密码登录期间唯一还起作用的限速手段。脚本只装过包、systemctl enable --now 过，判断不了你机器上的 jail 到底启没启用，所以只提醒不判断。

sudo fail2ban-client status sshd
输出含义处理
Status for the jail: sshd，带 Currently banned 与 Total bannedjail 已启用，正在计数与封禁不用动。顺手看一眼 Currently banned 里有没有你自己的出口 IP
Sorry but the jail 'sshd' does not existfail2ban 装了，jail 没启用，等于零防护在 /etc/fail2ban/jail.local 补 sshd 段后 systemctl restart fail2ban；不补就把 PasswordAuthentication 改回 no
command not foundfail2ban 没装同上一行；机器上没公钥可用时先装，否则别开密码登录
  • 非标端口不额外配置。jail 认的是 sshd 写进日志的失败行，封禁动作针对 IP、不分端口，4061 与 22 一视同仁。
  • 日志后端要对得上。系统里没有 syslog 时 fail2ban 读不到文件日志，需要 backend = systemd，否则 Total failed 一直是 0，看着像在跑其实没在数。
  • 试密码会把自己封掉。maxretry 默认 5 次 / 10 分钟，从同一出口 IP 反复试密码就触发封禁。解封：sudo fail2ban-client set sshd unbanip <你的IP>。

验证密码登录

公钥可用时客户端先拿公钥认证过去，密码这条路根本不会走到，所以必须显式关掉公钥再试。命令末尾的 true 是被执行的远程命令：认证通过就以退出码 0 收场，不回显任何内容。没有输出不等于失败，这是最容易误判成「密码被拒」的一处。

ssh -o PubkeyAuthentication=no -o PreferredAuthentications=password \
    -o KbdInteractiveAuthentication=no -o NumberOfPasswordPrompts=1 \
    -o ConnectTimeout=5 -p <SSH端口> root@<服务器IP> 'whoami; hostname'; echo "exit=$?"
现象含义
静默返回，回显 exit=0密码登录成功。远程命令是 true 时只有这个结果，没有别的输出可看
回显 root 与主机名，exit=0同上，把远程命令换成会打印的
Permission denied (publickey,password).sshd 提供了密码方法，凭据被拒：密码不对，或账号、PAM 层拒绝
Permission denied (publickey).密码方法没被提供：passwordauthentication 没生效
连接超时、无响应被 fail2ban 或 PerSourcePenalties 封禁，与密码无关

要进交互 shell，去掉末尾那段远程命令：

ssh -o PubkeyAuthentication=no -o PreferredAuthentications=password -p <SSH端口> root@<服务器IP>

服务端用日志交叉确认：sudo journalctl -u ssh -n 20 --no-pager | grep -i accepted，出现 Accepted password for root from … 即闭环。

客户端各自还原

服务端脚本只动服务器，够不到任何客户端的 home 目录。这一行是把手动步骤转交给每台客户端：凡是在本机跑过 20-client.sh 的机器，各自执行一次。

bash 90-uninstall.sh --client           # 摘掉 ~/.ssh/config 里的托管块，删脚本生成的 ~/.fwknoprc
bash 90-uninstall.sh --client --purge   # 再删本地 spa-keys.env，交互式会先问一次

还原是纯清理，不需要密钥包；只有 --purge 才碰 spa-keys.env。同目录下要有 20-client.sh，不需要 root。先确认要不要跑：

bash 90-uninstall.sh --client --check   # 转调 20-client.sh --status
两种情况脚本不会删 ~/.fwknoprc。文件里没有「由 20-client.sh 生成」标记时不删，那是 fwknop 装完自带的样例或你自己写的；本来就没有托管块时也无事可做，输出「无托管块」即为正常。服务端已经 --purge 过的话，本地那份密钥包敲不动门了，留着的价值只在于对账。

锁门急救

万一还是锁了——云厂商控制台的 VNC / 串口，或者你之前装了 Tailscale（见 第 5 页）。端口按探测结果恢复，不是 22：

sudo systemctl stop fwknop-server
sudo iptables -D INPUT -j FWKNOP_INPUT
ss -tlnp | grep sshd          # 看看真实端口
sudo ufw limit 那个端口/tcp

或者直接让脚本还原，它会自己探测端口，参数见 服务端参数：

sudo bash 10-server.sh --uninstall     # 还原 fwknopd.conf，恢复公网 SSH 规则
sudo bash 10-server.sh --purge         # 上面这些，再删掉 access.conf 与密钥包
