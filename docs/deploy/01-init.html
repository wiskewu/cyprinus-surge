1 · 系统初始化

把刚拿到的机器初始化到可安全登录的状态：依赖、时区与 swap、BBR、时间同步、SSH 加固、防火墙。执行者在服务器上以 root 操作，每一步都幂等，失败可以重跑。

目标

跑完这一步，机器应满足：内核 BBR 生效、有 1G swap、时间与 NTP 同步、SSH 只接受公钥登录、ufw 只放行实际监听的 SSH 端口与后续要用的服务端口。所有改动都能重复执行，不做破坏性清理。

准备工作

  • 云控制台的 VNC 或串口可用，作为失联时的兜底入口
  • 本机有可用的 SSH 密钥，能先完成一次公钥安装
  • 确定 SSH 端口：默认 22，建议改成高位端口，理由见本节最后一条
  • 确认虚拟化类型是 KVM，LXC / OpenVZ 开不了 TUN

22 端口本身就可能不通。某些网络对 22 端口做 RST 注入，表现是 TCP 连上、banner 之前就 Connection reset by peer，ufw 放行了也没用。所以别把 22 当作可用后备通道，挑一个高位端口，本手册示例用 4061。

实施步骤

上传脚本并登录

# 在你自己电脑上执行
scp -r bin root@你的服务器IP:/root/

ssh root@你的服务器IP

运行初始化

cd /root
bash bin/deploy/one/system.sh

# 正在把 sshd 换到新端口：先开新口再改配置
SSH_PORT=新端口 bash bin/deploy/one/system.sh

脚本会装依赖、开 BBR、加 1G swap、开时间同步、把 SSH 收成仅公钥登录，并把防火墙收成「只放行 SSH 端口、443/tcp、8443-8447/udp」。幂等，可以重复跑。

防火墙按实际在监听的端口放行：脚本从当前会话的 SSH_CONNECTION、ss 的监听表、以及运行中的 ssh.socket 取端口，只放行这些端口。SSH_PORT 不是必填项，它的两个作用见参数说明。

SSH 加固的三处细节

脚本会写 /etc/ssh/sshd_config.d/99-proxy.conf 关闭密码登录，但 sshd 对每个关键字只取「第一个出现的值」，所以 drop-in 不一定算数：

  • Ubuntu 镜像自带 50-cloud-init.conf 里写着 PasswordAuthentication yes，50 排在 99 前面，它赢。脚本会就地改掉这个文件，原文件备份为 .orig。
  • 有些镜像的 sshd_config 没有 Include sshd_config.d 一行，部分云厂商自定义镜像即如此，那 drop-in 就是死文件，密码登录字面没变。脚本会补一条 Include /etc/ssh/sshd_config.d/*.conf 到文件最顶部，备份为 sshd_config.before-include，sshd -t 不过就回滚。
  • 两种都处理完还不行时，脚本会把当前生效值和设置该关键字的位置一并列出，排除自己的 .orig 备份，照着改靠前那个。

上一轮报过 [!] 未生效：/etc/ssh/sshd_config 里可能没有 Include sshd_config.d 的，属于第二条。把脚本重新 scp 上去重跑，或手工补一行：

grep -qiE '^[[:space:]]*Include[[:space:]]' /etc/ssh/sshd_config || \
  sed -i '1i Include /etc/ssh/sshd_config.d/*.conf' /etc/ssh/sshd_config
sshd -t && systemctl restart ssh && sshd -T | grep -i '^passwordauthentication'
没有公钥就不会关密码。脚本先检查 authorized_keys，为空就跳过加固并提示。先用 ssh-copy-id 装好公钥，再重跑这一步，否则一台还没配过密钥的机器会被直接锁死。

加固被跳过时的补做顺序

加固被跳过意味着密码登录还开着，所以现在进得来，装公钥也进得来。整套动作从你自己的电脑开始：

# 1) 把本机公钥装到服务器（端口换成实际端口）
ssh-copy-id -p 你的SSH端口 root@服务器IP

# 2) 另开一个新会话验证：只允许公钥也得能进
ssh -o PreferredAuthentications=publickey -o PasswordAuthentication=no -p 你的SSH端口 root@服务器IP true && echo 公钥OK

# 3) 回服务器重跑本步
cd /root && SSH_PORT=你的SSH端口 bash bin/deploy/one/system.sh

看到 [+] 已生效：passwordauthentication no 就成了，可用 sshd -T | grep -i '^passwordauthentication' 复核。不要先手动关密码登录再跑脚本，那才是真死循环。

只能用云控制台、本地没有 SSH 客户端时，把公钥贴进去一样管用：

mkdir -p ~/.ssh && chmod 700 ~/.ssh
echo 'ssh-ed25519 AAAAC3Nza... 你备注' >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys

把 SSH 挪到非 22 端口

脚本不会改 sshd 的端口，只负责放行。挪端口一律「先开新、再关旧」：

# 1) 两层都先放行新端口：ufw + 云厂商安全组
ufw allow 4061/tcp
# 已部署过的机器也可以改用：SSH_PORT=4061 bash bin/deploy/one/system.sh
# 它会同时放行两个端口，以后再跑就只剩实际在听的那个

# 2) 改 sshd（没有 Port 行就追加到末尾）
sed -i 's/^#*Port .*/Port 4061/' /etc/ssh/sshd_config
grep -qi '^Port' /etc/ssh/sshd_config || echo 'Port 4061' >>/etc/ssh/sshd_config
sshd -t && systemctl restart ssh

# sshd 由 socket 激活时（systemctl cat ssh.socket 有 ListenStream=22）还要改 socket：
#   mkdir -p /etc/systemd/system/ssh.socket.d
#   printf '[Socket]\nListenStream=\nListenStream=4061\n' > /etc/systemd/system/ssh.socket.d/override.conf
#   systemctl daemon-reload && systemctl restart ssh.socket

# 3) 另开一个终端确认能进（当前会话先别关）
ssh -p 4061 root@服务器IP

# 4) 确认无误再关旧端口：ufw delete allow 22/tcp，安全组里删 22
已经把自己挡在外面时，从云控制台 VNC 或串口进去执行 ufw allow 你的端口/tcp，应急可先 ufw disable，具体见排查手册的「SSH 端口连不上」。

检查与验证

systemd-detect-virt                        # kvm
test -c /dev/net/tun && echo TUN-OK        # TUN-OK
sysctl net.ipv4.tcp_congestion_control     # bbr
sshd -T | grep -i '^passwordauthentication'    # passwordauthentication no
ss -tlnp | grep -E 'sshd|:22'              # sshd 实际在听哪个端口
ufw status                                 # 放行的端口与上面这条一致

ufw 只是里层。云厂商控制台里的安全组是外层，脚本碰不到，需要在控制台手工放行同样的端口：

端口协议谁用
SSH 端口（默认 22）TCP登录用
443TCPREALITY 主入口
8443–8447UDPHysteria2 备入口与端口跳跃，ENABLE_HY2=0 时用不到
两层都要配。典型症状是 443 通但 8443 超时，或反过来，同一个服务不同端口表现不一致。这时不是配置错，是外层还没放行。

回退与卸载

本步只做系统层配置，回退分两类。整个项目的清除见总览的卸载命令；只撤销防火墙与内核参数时，用下面的命令逐项恢复：

sudo ufw disable                        # 临时关闭防火墙，确认能连通后再按需重开
sudo ufw delete allow 443/tcp           # 删掉本步加的放行规则
sudo rm -f /etc/sysctl.d/99-proxy.conf  # 移除 BBR 与缓冲参数文件
sudo sysctl --system
先确认 SSH 会话还开着再动防火墙。关闭 ufw 会放开全部端口，恢复时若漏掉 SSH 端口就会失去连接，此时只能走控制台。

命令手册

# 应用（幂等，可重复执行）
bash bin/deploy/one/system.sh

# 挪端口过渡期：新端口尚未监听也一并放行
SSH_PORT=4061 bash bin/deploy/one/system.sh

# 核对
sysctl net.ipv4.tcp_congestion_control
sshd -T | grep -i '^passwordauthentication'
ufw status numbered
ss -tlnp | grep -E 'sshd|:22'

参数说明

项取值作用
SSH_PORT端口号挪端口过渡期显式放行新端口；探测不到 sshd 监听端口时作为唯一依据，未给则用 22

探测到监听端口时，与它不符的 SSH_PORT 不会被放行。deploy.env 里的历史值（早期版本写死 SSH_PORT=22）属于这一类，脚本会删掉自己以前加的冗余规则，并把该行改写成真实端口。日志形如：

[!]     SSH_PORT=22 未在监听，本次不放行；实际监听：4061
[!]     已移除冗余 SSH 规则：22/tcp（sshd 未监听，且本次未要求放行）
[+]     SSH 端口：4061
ss -tlnp | grep -E 'sshd|:22'        # 实际监听（socket 激活时看 systemctl cat ssh.socket）
sshd -T | grep -i '^port'            # 配置里写了什么，不等于现在在听什么

现象原因处理
第 6 项报「未生效」并列出多个文件排序靠前的文件写了同一关键字，或 sshd_config 没有 Include 行按脚本列出的位置改靠前那个；缺 Include 时补一行并 sshd -t

ufw 里多出 22，而 sshd 不在 22deploy.env 里残留早期写死的 SSH_PORT=22重跑 bin/deploy/one/system.sh，它会删掉冗余规则并改写该行
