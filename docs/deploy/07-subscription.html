订阅与用量显示

主读者：需要把服务器用量与探针状态显示到客户端的人。本页是参考资料，记录商用机场的做法与本仓库选取的折中方案。

商用机场的标准做法

订阅链接除了返回配置正文，还会带几个 HTTP 响应头。客户端读头，把用量与到期显示在订阅卡片上。核心是 subscription-userinfo：

subscription-userinfo: upload=1234; download=2234; total=1099511627776; expire=1798761600
content-disposition: attachment; filename="vps.yaml"
profile-update-interval: 24
profile-web-page-url: https://example.com
头含义取值
subscription-userinfo用量与到期upload / download / total 为字节，expire 为 Unix 时间戳
content-disposition配置文件名attachment; filename="x.yaml"，中文需 UTF-8 百分号编码
profile-update-interval自动更新间隔小时
profile-web-page-url订阅卡片上的主页入口URL

三个容易踩的坑

坑说明
UA 判断多数实现只对含 clash 的 UA 返回该头，用浏览器直接打开看不到
proxy-providers 不显示用节点源方式引用订阅时，客户端拿不到卡片级元信息，流量与到期不显示；必须用「远程配置文件」方式导入
sing-box 不支持订阅官方以「不在客户端解析代理分享格式」为由关闭了订阅支持，sing-box 系 GUI 不认这些头

本仓库的做法

客户端里能看到的名称就是出站 tag，所以把用量直接写进 tag，不引入订阅服务：

vps · 3.6G/1T         正常
vps · 3.6G/1T ⚠       最近一次探针发现服务、端口、AI 出口或丢包异常
项来源说明
用量vnstat --json m当月收发合计，配额取 MONTHLY_QUOTA，默认 1T
异常标记probe.log 最后一行，且不早于 PROBE_MAX_AGE_MIN 分钟（默认 15）出现 down 或 AI 出口 fail 时追加一个符号，只用单个字符避免名称过长
刷新时机重渲染名称是快照，客户端不会自己更新；改用量要重跑客户端渲染并重新分发

这是快照而非实时。要实时刷新必须走订阅服务，代价见下节。

告警

monitor.sh 在探针之后评估阈值，命中即推送。阈值都可用环境变量覆盖：

变量默认含义
ALERT_TRAFFIC_PCT80当月流量占比阈值
ALERT_CERT_DAYS14证书剩余天数阈值
ALERT_COOLDOWN_H6同一告警的冷却小时数
ALERT_TG_TOKEN / ALERT_TG_CHAT空Telegram 推送凭据
ALERT_WEBHOOK空通用 webhook，POST JSON 正文 {"text": "..."}
 
sudo bash bin/deploy/ops/monitor.sh --alert-test     # 验证推送凭据
sudo bash bin/deploy/ops/monitor.sh --alert-check    # 只评估，不发探针

两种推送都没配时，异常只写进 probe.log，不影响探针本身。

探针停摆时不会误报。定时器没跑、文件停在几小时前，最后一行不会自己消失。异常标记与告警检查都只认 PROBE_MAX_AGE_MIN 分钟内的记录，超龄就当没有数据。要调整窗口：PROBE_MAX_AGE_MIN=30 bash bin/deploy/client/render.sh ./client.env。

推送通道

alert_send 支持同时配置多个通道，任一成功即算送达。下列通道在大陆可直连：

通道变量费用与限制
企业微信 / 钉钉 / 飞书群机器人ALERT_WECOM_WEBHOOK免费，需建群并加机器人，每分钟约 20 条
Server酱ALERT_SERVERCHAN_KEY免费每天 5 条，落到微信；付费约 39 元每年可到每天 1000 条
SMTP 邮件ALERT_SMTP_URL / ALERT_SMTP_USER / ALERT_SMTP_PASS / ALERT_MAIL_TO用邮箱服务商的授权码即可，如 smtps://smtp.qq.com:465
通用 webhookALERT_WEBHOOKPOST JSON {"text": "..."}，可对接自建服务
TelegramALERT_TG_TOKEN / ALERT_TG_CHAT服务器通常需要代理，不建议作为主通道

告警量小，任选其一即可；建议至少配两个通道，避免单通道故障时告警变成聋子。

改走标准订阅的代价

要显示实时用量与到期，需要独立的 HTTP 服务：读取 vnstat 与配额，生成配置正文并附上响应头。代价是三处新增：

  • 一个常驻服务与一个对外端口。当前 443/tcp 被 REALITY 占用，订阅只能另开端口，并靠 token 保护。
  • 一套 token 分发与轮换机制，等价于再维护一份凭据。
  • Clash 系需要 YAML 格式，现有模板是 sing-box JSON，要另写一份模板。

设备数量少、只有一两个人使用时，节点名方案覆盖了同样的信息，不值得为此增加一个公开服务。
