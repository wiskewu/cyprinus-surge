4 · 可选：Hysteria2 第二入口

不做也可以，REALITY 单入口已经能用。需要你有一个域名，DNS 托管在 Cloudflare。

准备

  1. 加一条 A 记录指向你的服务器 IP，关闭 Cloudflare 代理（灰云）
  2. 创建 API Token，权限选「编辑区域 DNS」

执行

cd /root/deploy
bash bin/deploy/one/hy2.sh        # 输入域名 / 邮箱 / Token，自动签发并续期
bash bin/deploy/one/server.sh  # 服务端开始监听 UDP
bash bin/deploy/check/server.sh

# 可选：让客户端的端口跳跃真正可用
bash bin/deploy/one/port-hop.sh

完成后要回到客户端重新渲染一次配置（它会读到 ENABLE_HY2=1）。

验证 hy2 真的生效

客户端渲染出来的配置会多一个 proxy-hy2 出站，与 proxy 一起挂进 auto。auto 是个 urltest，route.final 指向它，所以「出口是服务器 IP」说明不了任何事，很可能一直是 REALITY 在承载。要证明 hy2 可用，得单独把它拎出来跑。

1. 服务端在监听

systemctl is-active sing-box
ss -ulnp | grep ':8443'          # hysteria2 走 UDP，用 -u
sudo bash bin/deploy/check/server.sh     # 自带「UDP 8443 在监听」一项

云安全组与 ufw 要放行 8443-8447/udp。只放 8443 时端口跳跃会随机失败，现象是「时通时不通」。

2. 客户端配置的形状

jq -r '.outbounds[] | "\(.tag)\t\(.type)"' client.json
# proxy      vless
# proxy-hy2  hysteria2
# auto       urltest
# direct     direct
jq -r '.route.final' client.json          # ENABLE_HY2=1 时应为 auto

3. 一条命令验证：HY2_ONLY=1

验收脚本会从你手上的配置派生一份副本：所有指向其它代理出站的引用改写成 proxy-hy2，出站裁到只剩 proxy-hy2 与 direct，入站换成一个本地 mixed 端口，然后前台跑起来验收、跑完自动清理。不改你原来那份配置，也不用 root。

HY2_ONLY=1 CONFIG=./client.json bash bin/deploy/client/verify.sh ./client.env

# 只给变量、没有 client.env 时
HY2_ONLY=1 CONFIG=./client.json SERVER_IP=你的服务器IP VLESS_PORT=443 \
  bash bin/deploy/client/verify.sh
变量默认作用
HY2_ONLY=1关派生配置 + 起临时实例 + 跑完整验收，需要本机有 sing-box
HY2_ONLY=emit关只生成一份只走 hy2 的配置，不起进程、不联网、不需要 sing-box
CONFIG./client.json要派生的客户端配置，bin/deploy/device.sh 生成的 *-desktop.json 直接用
HY2_TAGproxy-hy2出站 tag，改了模板或手写过配置时用
HY2_PROBE_PORT2081临时 mixed 入站端口，与 GUI 的 2080 错开
SING_BOX_BINsing-box要执行的二进制，非 PATH 里的可写绝对路径
HY2_OUThy2-only.jsonemit 模式的输出文件

退出码沿用脚本的约定：0 全过 / 1 有失败项 / 2 临时实例没起来或本地代理不可用。临时实例的日志留在系统临时目录里，失败时脚本会把尾部打出来。

本机要有 sing-box 且不能与 GUI 抢端口。缺二进制时脚本直接退出并提示装法；GUI 开着 TUN 时先断开，或把 HY2_PROBE_PORT 换成别的空闲端口。派生配置只保留本地 mixed 入站，所以不需要 root。

装了图形客户端但没有 CLI 时

SFM、GUI.for.SingBox 这类客户端把核心装在 App 或系统扩展里，PATH 上没有可执行的 sing-box。用 emit 生成一份只含 hy2 出站的配置，导入客户端即可，不必装第二个核心：

HY2_ONLY=emit CONFIG=./client.json HY2_OUT=./hy2-only.json \
  bash bin/deploy/client/verify.sh
生成结果说明
出站只剩 proxy-hy2 与 direct原来的 auto 与 proxy 被移除，所有引用改指 proxy-hy2
route.final = proxy-hy2没有代理组可选，导入后必然只走 hy2
dns.servers[].detour、http_clients[].detour、route.rules[].outbound同样改指 proxy-hy2，不留悬空 tag
入站原样保留TUN 与本地混合端口都不动，交给客户端自己的隧道管理

导入后按客户端分配到的本地端口跑普通验收，所有检查都会经由 hy2：

PROXY=socks5h://127.0.0.1:<客户端端口> SERVER_IP=<服务器IP> \
  bash bin/deploy/client/verify.sh

emit 不读 client.env、也不联网，所以没有那份文件也能用。两种模式的分工：emit 只落到文件，HY2_ONLY=1 自己起进程跑，后者需要本机有 sing-box 二进制，前者不需要。

图形客户端的 TUN 会抢路由。验收走的是客户端自己的本地端口，与 TUN 是否开启无关；但 TUN 在跑时命令行测出来的延迟会被它接管，看 route -n get 8.8.8.8 | grep interface 确认。

4. 抓包确认走的是哪一个

# 客户端：hy2 是 QUIC over UDP；REALITY 是 TCP 443
sudo tcpdump -ni en0 'udp portrange 8443-8447' -c 20
sudo tcpdump -ni en0 'tcp port 443' -c 20

只有区间内的 UDP、没有到服务器的 TCP 443，才是 hy2 在承载。server_ports 生效时，抓到的目的端口会在 8443–8447 之间变化。服务端对账：

sudo tcpdump -ni any 'udp portrange 8443-8447' -c 10
sudo journalctl -u sing-box -n 100 --no-pager | grep -iE 'hysteria|hy2'

5. urltest 选不选它

auto 每 3 分钟测一次 https://www.gstatic.com/generate_204，tolerance 为 100ms：只有候选比当前快出 100ms 才会切换。REALITY 通常先测赢，hy2 长期备而不用，这不算配置错误，是主备设计。想让它常驻，把 auto.outbounds 收成只剩 proxy-hy2，或把 route.final 指向 proxy-hy2。

常见失败点

现象原因与处理
QUIC 握手失败，日志里几乎没有有效信息两端 obfs salamander 密码不一致，对比 out-hy2.json.tmpl 与 in-hy2.json.tmpl 渲染出来的值
TLS 报 SNI / 证书错误客户端 tls.server_name 与服务端证书域名不一致
本地抓包有 UDP 出去，服务端抓不到UDP 出境被拦，校园网与公司网常见
8443 通，跳到区间内其它端口就失败外层安全组只放了 8443，补 8443-8447/udp
HY2_ONLY=1 报临时实例没起来看脚本打出的日志尾部：多半是 CONFIG 里没有 proxy-hy2，或派生配置 sing-box check 不通过
