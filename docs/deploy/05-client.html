5 · 客户端

目标：拿到属于这台设备的那一份配置，导入客户端并跑起来。凭据由服务器按设备发放，一台设备一份；客户端机器不需要 client.env、不需要密钥包，也不需要仓库里的脚本。

取配置

配置在服务器上渲染与打包，客户端只负责接收、校验、导入。

# 服务器：名单里没有这台时先建凭据，再打包
sudo bash bin/deploy/device.sh add laptop
sudo bash bin/deploy/device.sh export laptop

# 客户端：先校验再解包（-P 是 SSH 端口；export 会打出填好端口、用户与地址的完整命令）
scp -P 你的SSH端口 root@服务器IP:/etc/sing-box/clients/dist/laptop-*.tar.gz* /tmp/
cd /tmp && sha256sum -c laptop-*.tar.gz.sha256 && tar -xzf laptop-*.tar.gz

在 ~/.ssh/config 里配好 Host vps / HostName 服务器IP / User root / Port 你的SSH端口 之后，上面那行可以写成 scp vps:/etc/sing-box/clients/dist/laptop-*.tar.gz* /tmp/。macOS 没有 sha256sum，用 shasum -a 256 -c laptop-*.tar.gz.sha256。

解出来的文件名形如 sing-box-client-laptop-desktop.json：中间是设备名，末尾是平台。包里只有这一台设备的配置与 SHA256SUMS。

平台产物入站适合
desktop-desktop.jsontun + mixed:2080Windows / macOS / Linux，命令行也能直接验收
android-android.jsontunsing-box 官方 App
ios-ios.jsontunSFM 等 iOS 客户端

平台在 add 时决定：sudo bash bin/deploy/device.sh add phone android。同一台机器要用两个平台，就按两个名字建两条凭据，各自能单独吊销。

桌面那份配置的本地端口是 127.0.0.1:2080，验收脚本默认就用它。图形客户端自带端口设置时以界面为准，验收时显式传 --proxy。

GUI.for.SingBox 的订阅与规则

GUI.for.SingBox 不把整份配置当订阅：它的订阅只吃 sing-box 的 outbounds 节点数组，路由、DNS、入站都由「配置」页自己生成。两者填错任一处，内核启动即失败。

订阅填节点，不填配置

订阅内容只放真实节点，也就是设备 JSON 的 outbounds 里 type 为 vless 与 hysteria2 的两项。整份配置也能被它读进来，但 urltest、direct 会被 excludeProtocol 丢掉，等于什么都没留下：

[
  { "type": "vless", "tag": "vps-reality", "server": "hy2.example.top", "server_port": 443,
    "uuid": "……", "flow": "xtls-rprx-vision",
    "tls": { "enabled": true, "server_name": "www.apple.com",
             "utls": { "enabled": true, "fingerprint": "chrome" },
             "reality": { "enabled": true, "public_key": "……", "short_id": "……" } } },
  { "type": "hysteria2", "tag": "vps-hy2", "server": "hy2.example.top", "server_port": 8443,
    "server_ports": ["8443:8447"], "password": "……",
    "obfs": { "type": "salamander", "password": "……" },
    "tls": { "enabled": true, "server_name": "hy2.example.top" } }
]

两段内容从设备 JSON 原样拷过来即可，不要改字段名。订阅导入后点「更新」，节点数应为 2。

规则页三处必须填全

位置必须填漏了会怎样
出站的分组组里加入订阅节点，或填包含关键词；另需一个 direct 出站生成 "outbounds": []，内核报 initialize outbound[N]: missing tags
DNS 规则每条规则都选「服务器」生成缺 server 的规则，内核报 parse dns rule[N]: missing server field
路由规则每条 route 规则的出站必须指向存在的出站指向已删除的分组时，启动报 dependency[X] not found for outbound[Y]；不指出站则该条不生效，服务器直连规则会失效
GUI 不校验这些空值。组为空、DNS 规则没选服务器、路由指向已删的出站，界面都能保存并生成 JSON，只有启动内核时才报错。改完规则先用 sing-box check 验一遍再启动。

用源文件手写时的四个易错点

  1. 组里写了成员 tag 却忘了把成员出站本身写进 outbounds：内核在连接阶段报 dependency[proxy] not found。
  2. DNS 规则照抄 {"action": "route", "rule_set": ["geosite-cn"]}：1.12 起 route 动作必须带 server。
  3. 路由规则照抄 {"action": "route", "ip_cidr": ["…/32"]}：不报错，但这条不再指向 direct，服务器 IP 会被送进隧道，SSH 立刻被断。
  4. 节点名里的分隔符在 GBK 环境下可能变字：vps · 4.5G 被转成 vps 路 4.5G，组与成员 tag 就对不上了。跨工具复制时把名字改成纯 ASCII，例如 vps-4.5G。

验收

图形客户端把核心装在扩展或 App 里，本机没有 sing-box 可执行文件。免 CLI 子集只借客户端已经开好的本地端口：

SERVER_IP=你的服务器IP bash bin/deploy/client/verify.sh --no-cli --proxy socks5h://127.0.0.1:2080
检查项免 CLI 子集完整验收
代理可用与境外出口有有
分流：国内站点是否直连有有
AI 站点可达性有有
出口是否稳定有有
延迟分解跳过，需要读配置有
握手质量跳过，需要 SERVER_IP 与 mtr有
这是子集，不是完整验收。跳过项与 SERVER_IP 缺失都会明确打印，不会被当成通过。整机都走隧道时「国内直连」一项会判失败，那是环境决定的，不代表客户端有问题。

规则集缓存

分流依赖远程规则集，配置里已写入 experimental.cache_file：下载与编译结果落盘，重启不再整份重下；规则集自身的 update_interval 是 3 天，到期由 sing-box 自行刷新。

发给客户端的配置里，缓存路径是相对路径 cache.db，由客户端解析到自己的运行目录。要固定位置，在服务器渲染前给 SING_BOX_CACHE_FILE 指一个客户端上存在的路径。

写法有版本要求。1.13 起顶层 cache_file 被移除，必须写在 experimental.cache_file 里且为对象形式 {"enabled": true, "path": "..."}；写成字符串会被 sing-box 拒绝启动。服务器模板已按新写法生成，客户端不用改。

配置里已经处理好的两件事

  • 服务器 IP 直连。开着 TUN 时，连服务器的流量同样会被送进隧道，从隧道出口绕回这台 VPS，表现为「nc 能通但 ssh 立刻被关」。服务器渲染时按 SERVER_IP 写死了这条规则，客户端不用动。
  • 接口绑定。多网卡或虚拟网卡的 Windows 若在日志里看到 not valid in its context，说明这台机器需要显式绑网卡。把这个情况告诉服务器端，重渲染该设备时带 AUTO_DETECT_INTERFACE=false DEFAULT_INTERFACE=网卡名，再重新导出。只关探测不绑网卡会让直连打环，两者必须一起给。

macOS 只留一个客户端

两台代理客户端同时接管流量时，症状无法归因：断流、DNS 泄漏、TUN 抢路由三者互相掩盖。macOS 上统一用 SFM，其余客户端全部退出并停用系统代理。

操作清单

# 1. 关掉其他客户端的接管，退出 App（含菜单栏图标）
#    Clash Verge：设置里关「系统代理」，关「TUN 模式」，再退出

# 2. 确认系统代理已清空，三项都应为 Enabled: No 或不存在
scutil --proxy | grep -Ei 'HTTPProxy|HTTPSProxy|SOCKSProxy|ProxyAutoConfig'
networksetup -getwebproxy Wi-Fi
networksetup -getsecurewebproxy Wi-Fi
networksetup -getsocksfirewallproxy Wi-Fi

# 3. 确认没有残留的 utun 接口与默认路由
ifconfig | grep '^utun'
route -n get default | grep -E 'interface|gateway'

# 4. 只留 SFM：首次启动按提示授权系统扩展，再导入 JSON，最后打开 TUN

# 5. 确认默认路由进了 SFM 的 utun，且能出网
route -n get default | grep interface
curl -s -o /dev/null -w '%{http_code}\n' https://www.gstatic.com/generate_204
