6 · 验收、备份与运维

确认节点真的可用，留下能恢复的备份，并建立可观测与凭据轮换的日常机制。验收命令在客户端机器执行，备份与观测在服务器执行。

目标

本页做完应达到：客户端验收全过；服务器有一份加密备份且口令离线另存；探针按 5 分钟记录服务与出口状态；凭据可按需轮换并重新分发。

准备工作

  • 客户端已完成第 5 页，手上只有那份 JSON
  • 服务器可写 /root/backups，并已安装 gpg 或 openssl
  • 告警要推到手机时，先确定通道类型与凭据，取值见参数说明

实施步骤

客户端验收

验收脚本真正读的只有 SERVER_IP 与 VLESS_PORT，直接给变量即可：

SERVER_IP=你的服务器IP VLESS_PORT=443 bash bin/deploy/client/verify.sh

# 客户端端口不是 2080 时显式指定
SERVER_IP=你的服务器IP PROXY=socks5h://127.0.0.1:端口 bash bin/deploy/client/verify.sh

# 只验 Hysteria2 出站：脚本自己派生配置、起临时实例、跑完清理（需要本机有 sing-box）
HY2_ONLY=1 CONFIG=./sing-box-client-laptop-desktop.json SERVER_IP=你的服务器IP \
  bash bin/deploy/client/verify.sh

# 没有 sing-box 可执行文件：只生成一份只走 hy2 的配置，导入客户端后再验收
HY2_ONLY=emit CONFIG=./sing-box-client-laptop-desktop.json HY2_OUT=./hy2-only.json \
  bash bin/deploy/client/verify.sh

VLESS_PORT 默认 443，SERVER_IP 不给才会报错退出。它不是凭据，全设备通用，回服务器看一眼就知道：

grep SERVER_IP /etc/sing-box/client.env     # 只取 IP，不是拷走凭据
sudo bash bin/deploy/device.sh list                   # 确认这台在名单里
手机那份配置跑不了这个脚本。-android.json 与 -ios.json 只有 TUN，没有本地 2080 端口，第一项就退出码 2。手机只能在 App 里开浏览器自查，国内站点、Google、ChatGPT 各开一个；要用回环脚本就把桌面那份导进来测。

导出与分发

分发不只发一个 JSON：包里带校验和，收端先校验再解包，避免传输截断。

# 服务器：渲染 + 打包 + 出校验和，产物在 /etc/sing-box/clients/dist/
sudo bash bin/deploy/device.sh export laptop

# 客户端：先校验再解包
scp -P 你的SSH端口 root@服务器IP:/etc/sing-box/clients/dist/laptop-*.tar.gz* /tmp/
cd /tmp && sha256sum -c laptop-*.tar.gz.sha256 && tar -xzf laptop-*.tar.gz

包内只有这一台设备的配置与 SHA256SUMS，不含其他设备的凭据，也不含 client.env。clients/dist/ 下保留历史版本，文件名带 UTC 时间戳：

ls -1 /etc/sing-box/clients/dist/laptop-*.tar.gz | sort | tail -3

备份与加密

备份默认加密：优先 gpg --symmetric，没有 gpg 时退回 openssl enc，两者都缺失时脚本拒绝生成明文包。

sudo bash bin/deploy/ops/backup.sh key      # 首次：生成备份口令，打印一次
sudo bash bin/deploy/ops/backup.sh backup   # 加密备份
sudo bash bin/deploy/ops/backup.sh list     # 列出，标注明文还是加密
sudo bash bin/deploy/ops/backup.sh restore /root/backups/sing-box-xxx.tgz.gpg

备份含私钥，等同机器凭据，不要放网盘或仓库。/etc/sing-box 整个目录都会进包，所以 devices.list 与 clients/*.json 也在里面，一份备份等于全部设备的凭据。

观测：定时探针

节点出问题分两类：服务还在不在，出口有没有被风控。靠猜不准，用探针记成时序。

sudo bash bin/deploy/ops/monitor.sh              # 一键：装 5 分钟探针并立刻跑一次
sudo bash bin/deploy/ops/monitor.sh --probe      # 只跑一次探针
sudo bash bin/deploy/ops/monitor.sh --status     # 看最近 20 条记录与端口状态
sudo bash bin/deploy/ops/monitor.sh --uninstall
字段含义怎么用
tsUTC 时间戳对齐服务商故障与晚高峰
service / tcp / udpsing-box 状态、VLESS_PORT 是否监听、启用 Hy2 时 HY2_PORT/udp 是否监听先排除「进程挂了」
egress服务器直连 api.ipify.org 拿到的公网 IPIP 变了说明迁移或云厂商调度，客户端要重发配置
ai_code / ai_locchatgpt.com/cdn-cgi/trace 的状态码与出口地区出现 403 或 429 说明出口被风控，该换 AI 出口
loss_pct / rtt_avg_ms到 1.1.1.1 的丢包率与平均 RTT丢包长期高于 2% 时，Hy2 体验会明显劣于 REALITY

记录落在 /var/lib/sing-box-monitor/probe.log，只保留最近 5000 行；定时器是 sing-box-probe.timer，每 5 分钟一次。

凭据轮换

轮换会立刻让旧客户端配置失效，脚本在动作前要求确认，非交互环境必须显式给 --yes。

sudo bash bin/deploy/rotate.sh short-id        # 换 REALITY short_id
sudo bash bin/deploy/rotate.sh obfs            # 换 Hysteria2 obfs 密码，需 ENABLE_HY2=1
sudo bash bin/deploy/rotate.sh device main     # 换单台设备
sudo bash bin/deploy/rotate.sh devices         # 换全部设备
sudo bash bin/deploy/rotate.sh all             # 三项依次执行
sudo bash bin/deploy/rotate.sh all --dry-run   # 只打印计划

每次轮换都会重渲染服务端配置并重启 sing-box。收尾三步由脚本打印：重渲染客户端、让对方删除旧配置后重新导入、清理旧凭据所在的备份与聊天记录。

轮换不是吊销。只把凭据换掉，旧设备上的配置仍能读到旧凭据；确认作废要同时删除对应设备行，或用 bin/deploy/device.sh revoke。

检查与验证

vnstat -m                              # 本月流量（超配额后限速 1Mbps）
journalctl -u sing-box -n 50 --no-pager
bash bin/deploy/check/server.sh
sudo bash bin/deploy/ops/monitor.sh --status
sudo bash bin/deploy/ops/backup.sh list

验收通过的标准是脚本退出码 0 且七项全为通过；探针应能持续产出记录，--status 里服务与端口均为正常。备份核对三点：文件带 .gpg 或 .enc 后缀、list 标注为加密、口令文件存在且权限 600。

常见错误与排查

现象原因处理
恢复备份时提示口令错误口令文件被替换，或备份由另一台机器的口令加密找回原口令文件；找不到则加密包无法恢复，只能重建节点
备份产物是明文 .tgz用了 --insecure，或机器上既无 gpg 也无 openssl装 gpg 后重新备份；明文包按泄露处理
探针没有记录定时器未启用，或记录目录不可写systemctl status sing-box-probe.timer，再 monitor.sh --probe 手动跑一次看报错
告警一直没到手机未配置任何通道，或凭据错误先 monitor.sh --alert-test 发测试消息，确认通道可达
轮换后忘记重新分发客户端仍用旧凭据逐台 device.sh export 并重新导入；服务端日志会出现 processed invalid connection
手机验收第一项就失败移动端配置只有 TUN，没有本地端口改用桌面那份配置做回环验收，或在手机浏览器里自查
