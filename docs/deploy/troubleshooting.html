症状 → 原因 → 动作。这里的示例一律用占位符，不写真实地址。

国内站点全部打不开，境外却正常

两种已知原因，看日志区分。

① route.auto_detect_interface 取值和平台有关

场景取值原因
Android / iOS（TUN + auto_route）true（默认）直连出站必须绑到物理网卡，否则国内流量会绕回 TUN，表现为「国内无法直连」
Windows / macOS 桌面先 true；报错再改 false多网卡 / 驱动环境下接口绑定可能返回 10049，日志里是 not valid in its context
只用 mixed / 系统代理（无 TUN）无所谓没有路由改写，不需要绑定

桌面要覆盖成 false：AUTO_DETECT_INTERFACE=false bash 50-render-client.sh client.env（命令行优先于 client.env）。

Windows 多宿主 / 网卡驱动环境下，直连的 socket 会被绑到无效的本地地址，解析国内域名直接失败：

dial tcp <你的本地 DNS>:443: connectex: The requested address is not valid in its context

把它改成 false 即可。实测同一份配置只改这一个值：true → 请求失败、DNS lookup failed；false → DNS NOERROR、HTTP 200。

② 同时开了两个代理客户端

比如 Clash Verge 与 GUI.for.SingBox 同时运行：两边抢 DNS、抢系统代理、抢路由。症状同上，但还会看到 DNS 被改写成假地址（198.18.x.x 之类）。

处理：同一时间只留一个，退出另一个后重启留下的那个。

启动报 detour to an empty direct outbound makes no sense

sing-box 1.12+ 不允许 DNS 服务器的 detour 指向一个「空」direct 出站——也就是 {"type":"direct","tag":"direct"} 这种不带任何选项的直连：

FATAL start service: start dns-transport: start dns/https[dns-cn]:
      detour to an empty direct outbound makes no sense

两种改法，语义不同：

  • 删掉该 DNS 服务器的 "detour": "direct" → 跟随默认出站（通常是代理），解析要等隧道建好
  • 给 direct 出站加任一选项让它不再"空"，例如 "domain_resolver": { "server": "dns-cn" } → 国内域名仍走直连解析

本方案用第二种：国内域名直连解析，不依赖隧道。50-render-client.sh 生成的配置已经带上。

sing-box check 查不出这个错。check 不初始化 DNS 传输，所以「能导入 / 能过 check」不代表能启动——必须以真正启动一次为准。

GUI 报 missing tags 或 duplicate outbound tag

报错原因动作
initialize outbound[N]: missing tags某个 urltest / selector 分组的 outbounds 是空的节点没被登记进分组。用 GUI 的「编辑节点」手动加一次，或改用命令行跑完整配置
duplicate outbound/endpoint tag: direct订阅文件（或配置）里放了自己的 direct / block订阅里只放节点（vless / vmess / trojan / hysteria2…），不要放 direct / block / dns

注意：GUI.for.SingBox 生成的 config.json 是生成物，手改会被覆盖；要改就改订阅文件或 GUI 设置。GUI 的「订阅」只接受 outbounds 数组，不接受整份配置。

项不通过意味着动作

拥塞控制 / NTP内核模块没加载 / 时间漂移modprobe tcp_bbr && sysctl --system；systemctl restart systemd-timesyncd

起不来的常见原因

  1. 证书读不到：ENABLE_HY2=1 但没证书 → 跑第 4 步，或把它改成 0
  2. 端口被占：address already in use → 停掉占 443 的服务
  3. 变量缺失：变量 X 未设置 → 重跑 20-secrets.sh 或补上
  4. short_id 不是偶数长度 hex

日志里的 REALITY: processed invalid connection

不是故障。REALITY 对任何拿不到正确凭据的 TLS 连接都会记这一行，并把它转发给伪装站点。扫描器、浏览器直接访问服务器 IP、参数写错的客户端，都会产生它。

判断：看来源。不是自己的宽带地址 → 忽略；是自己的地址且客户端连不上 → 参数不匹配，对比这 6 项：服务器地址、端口、SNI、UUID、REALITY 公钥、short_id（外加 flow 必须一致）。

确认某条连接走了哪个出站

最直接的是客户端的「连接」列表：sing-box 的 Clash API 会给每条连接一个 chains 字段，["direct"] = 直连，["proxy"] = 走节点。

# 从客户端配置里读控制端口与密钥，再查连接列表
S=$(grep -o '"secret":"[^"]*"' config.json | cut -d'"' -f4)
C=$(grep -o '"external_controller":"[^"]*"' config.json | cut -d'"' -f4)
curl -s -H "Authorization: Bearer $S" "http://$C/connections" | grep -o '"chains":\[[^]]*\]' | sort | uniq -c

既有 direct 又有 proxy 才算分流正常；全是 proxy 说明国内直连规则没生效。

移动端闪退：NoSuchElementException（App 自身 bug）

java.util.NoSuchElementException
  at java.util.LinkedList.removeFirst(LinkedList.java:282)
  at io.nekohasekai.sfa.compose.screen.log.LogViewModel.togglePause(...)

崩在 日志页面点「暂停」的时候（日志列表为空）。这是 sing-box Android 客户端（SFA）的界面 bug，与应用配置无关。规避：不要在日志为空时点暂停；或升级 App。

解析失败：lookup 某域名: (exchange6: EOF | exchange4: EOF)

exchange6 / exchange4 是 sing-box 对同一个域名分别走 IPv6 / IPv4 的两次 DNS 查询。EOF 表示DNS 连接被关闭，常见原因：

  • 查询走的是「经代理」的 DNS（dns-remote），而那一刻隧道还没建好或握手失败
  • 代理刚重连，旧连接被关掉

当前配置下：国内域名走直连 DNS（不依赖隧道），只有海外域名才需要隧道。如果海外域名偶尔 EOF，先确认隧道已就绪再重试。

可以忽略的两条启动告警

  • implicit default HTTP client using default outbound for remote rule-sets is deprecated
    1.14 起不再隐式用默认出站下载规则集（1.16 会移除）。当前版本仍可用；升级到 1.16 前需要给每个 rule_set 指定 http_client。
  • REALITY: processed invalid connection（见上一节）
