## 0. 一页结论

| 层 | 选择 | 一句话理由 |
|---|---|---|
| 服务器 | 1C1G 优化线路 VPS（CN2 GIA / AS9929 / CMIN2），支持换 IP | 延迟由**线路**决定，不由配置决定 |
| 主入口 | **VLESS + XTLS-Vision + REALITY，TCP/443** | 2026 年 UDP 出境被大范围干扰，TCP/443 更像正常 HTTPS |
| 备入口 | **Hysteria2（QUIC/UDP + obfs salamander + 端口跳跃）** | 弱网/丢包/移动网络的吞吐兜底 |
| 客户端 | **sing-box 1.14.x 一份 JSON，三端 TUN** | 一份配置覆盖 Windows/macOS/Android，规则完全一致 |
| 分流 | `route` + 远程 `rule_set`（.srs），规则/全局双配置 | 规则可远程更新，不用写死 IP 表 |
| AI 出口 | **与主线路解耦的固定干净出口**（首选专用落地 VPS，静态 ISP 次之，WARP 仅兜底） | WARP 出口已被 OpenAI 定向拒绝过，不能当主出口 |
| IP 门禁 | IPQS Fraud Score ≤ 20 **且** 实测解锁通过 | 分数只是门票，解锁实测才是准绳 |
| 传输兜底 | BBR + 系统加固 + 证书自动续期 + 分时段监控 | 把「突然连不上」变成「可定位、可替换」 |

**和 readme 的三处关键修正（2026 版）**

1. **主备反转**：readme 建议「Hysteria2 为主、Reality 为辅」。但 2026 年 QUIC/UDP 出境被针对性过滤（GFW 自 2024-04 起能解密 QUIC Initial 做 SNI 过滤 `[研究]`；2026-04 社区报告全国性限制 UDP/443 出境 `[社区]`），电信骨干网尤为明显。**默认改为 Reality 主、Hysteria2 辅**，最终以你自己网络的实测为准（见 §5.3）。
2. **AI 出口优先级反转**：readme 建议「AI 流量优先走 WARP」。实测反例：OpenAI 已对特定 WARP IPv4 做 `SNI(chatgpt.com) + 源 IP` 的定向拒绝（2026-08 社区报告 `[社区]`），且 WARP 出口地区会漂移。**改为：固定干净出口为第一，WARP 只做零成本兜底**（见 §8.3）。
3. **配置语法更新**：sing-box 1.12 移除 GeoIP/GeoSite、1.13 移除 WireGuard 出站（改 `endpoints`）、1.14 改 DNS 规则写法 `[官方]`。网上绝大多数教程的配置在 1.14 上**起不来**，本方案配置按 1.14.x 编写（见 §4.4、§7.4）。

## 1. 把 5 条需求变成可验收的指标

「稳定」「干净」这类词无法验收，先量化。下表是本方案的验收基线，测试方法与通过标准同时给出。

| # | 需求 | 可测量指标 | 通过标准 | 测试工具 / 方法 |
|---|---|---|---|---|
| 1 | 全平台可用 | 三端同一份配置可用 | Windows 10+/macOS 12+/Android 10+ 均能导入并 TUN 生效 | sing-box 各端客户端 + `sing-box check -c config.json` |
| 2 | 服务器选项 | 规格 + 线路 + 可换 IP | 1C1G、月流量 ≥500GB、优化线路、支持换 IP 或按小时计费 | 厂商面板 + `iperf3` |
| 3 | 延迟 ≤500ms | ① 到 VPS 的 TCP 握手 RTT ② 代理后 `google.com` 首字节 TTFB | ① 晚高峰 ≤200ms（美西）/ ≤80ms（亚洲）② **≤500ms** | `mtr` / `tcping` / `curl -w '%{time_starttransfer}'` |
| 3b | 抖动与丢包（决定「稳」） | 晚高峰 jitter / 丢包率 | jitter ≤30ms、丢包 ≤1% | 200 次 `mtr` 统计，20:00–23:00 各测一轮 |
| 4 | IP 纯净度 | IPQS Fraud Score | **≤20**，且 `proxy/vpn/tor=false`、`recent_abuse=false` | IPQS 免费检测页（见 §8.1） |
| 4b | AI 可用性（分数之外） | ChatGPT 网页能登录并正常对话；无 1020 / 无限 challenge | 连续 3 天、每天 3 次人工验证通过 | 浏览器手动 + 清 cookie 复测 |
| 5 | 可分流 | ① 国内站点直连 ② AI 域名走独立出口 ③ 支持全局模式 | `curl ip.sb` 走代理；国内站点 traceroute 不出境；AI 出口 IP ≠ 主出口 IP；全局配置可切换 | Clash API 面板看连接走势 / `ifconfig.me` |

> 说明：500ms 是**很宽松**的预算。中美优化线路 Reality/Hysteria2 的典型值是 150–220ms `[社区]`，真正的体验瓶颈是**晚高峰抖动和丢包**，所以表中把 jitter/丢包单列为 3b 项。

## 2. 设计原则：三层解耦

自建代理的失效原因有三类，混在一台机器的一个 IP 上就会「一处崩、全崩」。本方案把它们拆成三层，每层可以独立替换：

| 层 | 要解决的问题 | 失效后的替换动作 | 不做什么 |
|---|---|---|---|
| **入口层**（抗封锁） | 连接能不能建立 | 换端口 / 换 short_id / 换协议入口 / 换 IP | 不承担 AI 风控 |
| **出口层**（纯净度） | 目标网站是否信任你 | 换 AI 出口（换 IP 或换落地区域） | 不承担抗封锁 |
| **分流层**（体验） | 谁走哪条路 | 更新规则集 / 改 `final` | 不承担前面两者的责任 |

这条原则是后面所有取舍的依据：**不要把所有需求压在一台机器的单一 IP 上。**

## 3. 总体架构

> 可视化入口：先打开 [`index.html`](index.html)（单文件方案可视化，可离线打开），其中内联了本方案的全部四张图。

分层视图与数据流见 [`diagrams/01-architecture.html`](diagrams/01-architecture.html)（archify 生成，独立交互版）。

```
[客户端 Windows/macOS/Android]
   sing-box (TUN / 系统代理)  ── 一份 JSON，三端一致
        │  分流在此完成
        ├── 国内域名/IP ────────────────────────► direct（直连，不绕行）
        ├── 普通境外流量 ──► 入口层 ─────────────► 主出口：VPS 原生 IP
        ├── AI 域名 ──────► 出口层（解耦）──────► AI 出口：固定干净 IP / WARP 兜底
        └── 广告/恶意 ──────────────────────────► reject

[入口层 = 同一台 VPS，双协议并行]
   主：VLESS + Vision + REALITY   TCP/443   （无域名、无证书、抗主动探测）
   备：Hysteria2                  UDP/8443  （obfs salamander + 端口跳跃）

[出口层]
   E1 主出口   = VPS 原生 IP        → Google / YouTube / 日常（带宽最大）
   E2 AI 出口  = 固定干净落地       → OpenAI / Anthropic / Gemini（地区固定）
   E3 兜底     = WARP 或商用节点    → 仅当 E2 不可用时临时顶上

[观测层]
   Clash API 面板（客户端） + 流量/健康探测（服务端） + 每周 IPQS/解锁复测
```

**为什么 AI 出口要独立**：机房 IP 在 OpenAI/Anthropic 风控里天然吃亏，而且「最便宜 + 低 Fraud Score + 全解锁」几乎不可能同时满足 `[推断]`。解耦后，YouTube/Google 继续走 VPS 本机带宽（快），AI 走另一条固定出口；某条路径出问题可单独定位和替换，不会连带影响另一条。

## 4. 服务器选项

### 4.1 线路等级（决定延迟与抖动）

| 线路等级 | 中国大陆典型 RTT | 晚高峰 | 参考价 | 定位 |
|---|---|---|---|---|
| **CN2 GIA**（AS4809） | 美西 130–180ms / 香港·日本 30–80ms | 抖动通常 <10ms | ≈$50–100/年起（特价）；香港/日本更贵 | 稳定优先的默认选择 |
| **AS9929 / CMIN2 / 软银** | 70–130ms | 白天优秀，晚高峰可能波动 | $10–30/月 | 性价比甜点 |
| **普通 163 / 国际 BGP** | 130–220ms | 晚高峰拥堵、丢包上升 | $3–10/月 | 备用机 / 试错机 |

结论：500ms 预算下，**不必为「最低延迟」付费，要为「晚高峰抖动小、可换 IP」付费**。代理中转不烧 CPU/内存，1 核 1G 足够；REALITY 握手略吃 CPU，单用户可忽略 `[推断]`。

### 4.2 厂商选项（2026-10 社区口碑，价格会变，下单前复核 `[社区]`）

| 厂商 / 产品 | 参考价 | 优点 | 注意 |
|---|---|---|---|
| 搬瓦工 CN2 GIA-E（DC6/DC9） | 特价约 $50/年；常规 $49.99/季 级 | KiwiVM 可**自由迁移机房**，线路试错成本最低；老牌不易跑路 | 特价常年缺货；贵 |
| DMIT LAX Pro / HKG Pro | LAX Pro ≈$100/年起 | AMD EPYC、带宽足、线路稳 | 常缺货；香港/日本价格高 |
| HostDare | ≈$37.49/年起 | 最便宜的 CN2 GIA，适合做**备用机** | 硬件一般 |
| 按小时计费的国际 BGP（Vultr / Linode / Akamai 等） | 按量 | 试错、临时落地、被封即销毁重建 | 不作长期主线路 |

### 4.3 选型硬条件（下单前逐条打勾）

- [ ] 支持**换 IP**或按小时计费（IP 整段被封时，换协议无效，只能换 IP `[推断]`）
- [ ] 独立 IPv4（不是 NAT 共享 IP），有 IPv6 更好但**必须能只走 v4 出站**
- [ ] 不与被大量代理滥用的热门 IP 段相邻（下单后 5 分钟内用 §8.1 验证）
- [ ] 月流量与带宽满足 4K YouTube（≥500GB、≥200Mbps 共享）
- [ ] 机房区域与你 AI 出口的**目标地区一致或接近**（账号地区一致性，见 §8.4）

### 4.4 服务器系统准备（Debian 13 / Ubuntu 24.04）

```bash
# 1) 基础加固
adduser me && usermod -aG sudo me
sed -i 's/^#\?PermitRootLogin.*/PermitRootLogin no/; s/^#\?PasswordAuthentication.*/PasswordAuthentication no/' /etc/ssh/sshd_config
systemctl restart ssh && apt install -y ufw fail2ban unattended-upgrades
ufw default deny incoming && ufw allow 22/tcp && ufw allow 443/tcp
ufw allow 8443:8447/udp      # Hysteria2 + 端口跳跃范围
ufw --force enable

# 2) 传输层优化（TCP 侧；QUIC 在用户态，但 socket 缓冲同样受益）
cat >/etc/sysctl.d/99-proxy.conf <<'EOF'
net.core.default_qdisc=fq
net.ipv4.tcp_congestion_control=bbr
net.core.rmem_max=16777216
net.core.wmem_max=16777216
net.ipv4.tcp_fastopen=3
EOF
sysctl --system && sysctl net.ipv4.tcp_congestion_control   # 期望输出 bbr

# 3) 时间同步（REALITY 要求客户端/服务端时间差在 max_time_difference 内）
timedatectl set-ntp true && timedatectl status

# 4) Hysteria2 需要域名 + 证书（REALITY 不需要）；用 DNS-01 避免占用 80 端口
curl https://get.acme.sh | sh -s email=you@example.com
~/.acme.sh/acme.sh --issue --dns dns_cf -d vps.example.com --server letsencrypt
~/.acme.sh/acme.sh --install-cert -d vps.example.com \
  --fullchain-file /etc/sing-box/cert.pem --key-file /etc/sing-box/key.pem \
  --reloadcmd "systemctl restart sing-box"
```

> `shortcut:` 证书续期靠 acme.sh 的 cron；如需更强的可观测性再换 systemd timer + 到期告警，不要在证书过期后才想起它。

## 5. 协议与入口设计

### 5.1 主入口：VLESS + XTLS-Vision + REALITY（TCP/443）

- 手握手伪装成访问**真实存在的第三方站点**（如 `www.apple.com`），对 DPI 与主动探测的隐匿性目前仍是第一梯队 `[社区]`。
- **不需要域名、不需要证书**，因此不存在证书过期这一失效源。
- 走 TCP/443：与正常 HTTPS 同端口，不受 UDP 限速策略影响。
- 关键配置约束（写错就起不来）：
  - `handshake.server` 必须与 `server_name` 一致，且该站点与 VPS **同区域、支持 TLS1.3 + HTTP/2**；
  - `short_id` 随机非空（`openssl rand -hex 4`）；
  - 客户端 `utls.fingerprint: "chrome"`；两端时间同步（`max_time_difference` 默认 60s）。

### 5.2 备入口：Hysteria2（QUIC/UDP）

- 基于 QUIC，Brutal 拥塞控制**不把丢包当拥塞信号**，弱网/抖动链路上更容易维持吞吐 `[官方]`。
- 2026 年必须叠加三件事才有可用性 `[研究][社区]`：
  1. **obfs salamander**：把 QUIC 包混淆成无特征随机字节，对抗「按 QUIC Initial 特征 + SNI 过滤」的检测；
  2. **端口跳跃**（`server_ports` + `hop_interval`）：对抗针对单端口 UDP 的 QoS/阻断；
  3. **客户端设 `up_mbps`/`down_mbps`**：触发 Brutal；不设则退化为普通 BBR。
- 代价：完全依赖 UDP。校园网/公司网/部分运营商可能直接限制 UDP `[社区]`。

### 5.3 谁做主入口：用实测决定，不要照抄

| 你的网络环境 | 建议主入口 | 依据 |
|---|---|---|
| 电信固网 | REALITY | 电信骨干对 UDP 限速最激进 `[社区]` |
| 联通 / 移动固网、蜂窝移动网络 | Hysteria2 | 这两张网对 QUIC 相对宽松 `[社区]` |
| 校园网 / 公司网（疑似封 UDP） | REALITY | 只有 TCP/443 可过 |
| 需要大流量下载 / 4K | Hysteria2 | Brutal 抗丢包 |
| 不确定 | REALITY 主 + Hy2 备，客户端用 `urltest` 自动测速切换 | 双入口本身就是容错 |

**切换与测速方法**：两个入站同时跑在同一台 VPS（不同端口，不冲突）。客户端为两者各建一个出站，用 `urltest` 组做 3 分钟一次的自动测速；或在 GUI 中手动切换。切换只在客户端发生，服务端无需改动。

### 5.4 服务端配置骨架（sing-box 1.14.x `[官方]` 语法）

```json
{
  "log": { "level": "warn", "timestamp": true },
  "inbounds": [
    {
      "type": "vless", "tag": "vless-in", "listen": "::", "listen_port": 443,
      "users": [{ "name": "me", "uuid": "<UUID>", "flow": "xtls-rprx-vision" }],
      "tls": {
        "enabled": true,
        "server_name": "www.apple.com",
        "reality": {
          "enabled": true,
          "handshake": { "server": "www.apple.com", "server_port": 443 },
          "private_key": "<REALITY 私钥>",
          "short_id": ["<8 位 hex>"],
          "max_time_difference": "60s"
        }
      }
    },
    {
      "type": "hysteria2", "tag": "hy2-in", "listen": "::", "listen_port": 8443,
      "up_mbps": 100, "down_mbps": 200,
      "obfs": { "type": "salamander", "password": "<混淆口令>" },
      "users": [{ "name": "me", "password": "<登录口令>" }],
      "tls": {
        "enabled": true,
        "server_name": "vps.example.com",
        "certificate_path": "/etc/sing-box/cert.pem",
        "key_path": "/etc/sing-box/key.pem"
      }
    }
  ],
  "outbounds": [{ "type": "direct", "tag": "direct" }],
  "route": { "final": "direct", "auto_detect_interface": true }
}
```

生成密钥与校验：

```bash
sing-box generate reality-keypair        # → PrivateKey / PublicKey
sing-box generate uuid
openssl rand -hex 4                      # → short_id
sing-box check -c /etc/sing-box/config.json   # 必须先通过再 systemctl restart
```

> `shortcut:` 服务端不做入站分流（本机只做出口），所以 `route` 极简；若以后要在 VPS 上做二次转发或落地分流，再补 `route.rules`。

## 7. 分流与 DNS

### 7.1 路由优先级（自上而下，先匹配先生效）

1. `action: sniff` —— 先拿到真实域名，否则下面所有域名规则都失效（Rev1 最常见的坑）
2. `protocol: dns` → `action: hijack-dns` —— DNS 查询必须被接管
3. 私有地址（`ip_is_private`）→ `direct` —— 局域网/内网不外发
4. **AI 域名**（`rule_set: geosite-openai` + 补充域名）→ `ai-out`
5. 广告/恶意域 → `reject`
6. `geosite-cn` + `geoip-cn` → `direct`
7. 其余 → 主出口（`final`）

### 7.2 规则代理 vs 全局代理

sing-box 本身不区分「模式」，模式差异只是**规则集与 `final` 的组合**：

| 模式 | 实现 | 适用 |
|---|---|---|
| 规则代理（日常） | 上面 7 条完整生效，`final = proxy` | 日常科研，国内站点直连不绕行 |
| 全局代理 | 删掉第 6 条（或把 `final` 强制为 proxy 且禁用 `geosite-cn/geoip-cn`） | 需要「所有流量看起来都在境外」的场景 |

维护两份配置 `config.rule.json` 和 `config.global.json`（同模板、差异替换），比在 GUI 里来回点更可复现。

### 7.3 DNS 防泄露（必须做）

- **国内域名**用国内 DoH（如 `223.5.5.5`，走 `direct` 出站）；**境外域名**用远端 DoH（`1.1.1.1`/`8.8.8.8`，走代理出站）。
- 禁止「明文 53 直连境外」：那既是泄露面，也容易被污染导致分流误判。
- `strategy: ipv4_only` 可少一次 AAAA 往返、降低首字节延迟；`independent_cache: true` 避免不同出站互相污染缓存。
- 验收：`dnsleaktest` / `browserleaks` 扩展检查，DNS 服务器归属地应与出口地区一致。

### 7.4 规则集来源（2026 版写法）

sing-box 1.12 起 **GeoIP/GeoSite 已移除**，必须用 `rule_set` `[官方]`：

| 规则集 | 来源 | 用途 |
|---|---|---|
| `geosite-cn.srs` | `SagerNet/sing-geosite` → `rule-set/` | 国内域名直连 |
| `geoip-cn.srs` | `SagerNet/sing-geoip` → `rule-set/` | 国内 IP 直连（兜底 CDN） |
| `geosite-openai.srs` | `SagerNet/sing-geosite` | AI 出口路由 |

建议用 `sing-box rule-set download` 预下载到本地并定期更新，避免「启动依赖境外网络」这一单点。

## 8. IP 纯净度与 AI 出口

### 8.1 用 IPQS 量化筛选（口径必须说清）

IPQS 的 Fraud Score 是 0–100，**越高越脏**。官方口径是「≥85 高度可疑、≥90 建议直接拦截」`[官方]`；readme 引用的「0–20 干净」来自第三方整理，属于**偏严格的社区口径** `[社区]`。本方案采用 ≤20 作为自建机的硬门槛，是**主动加严**，不是官方标准。

**下单后 5 分钟内跑完的门禁流程**：

| 步骤 | 看什么 | 通过标准 |
|---|---|---|
| 1 | IPQS 免费检测：`fraud_score`、`proxy`、`vpn`、`tor`、`recent_abuse`、`bot_status`、`ASN` | score ≤20，且 proxy/vpn/tor/recent_abuse 均为 false |
| 2 | ASN / IP 类型（ipinfo.io、ip.ping0.cc） | 明确 ASN；「原生 IP」≠「住宅 IP」，两者都要看 |
| 3 | 实测解锁：ChatGPT 登录 + 连续对话、Gemini、Claude、Google 搜索是否弹验证码 | 无 1020、无无限 challenge |
| 4 | 不合格 | **立即换 IP 或换机**，不要先部署再发现 |

> 关键认知：**低 Fraud Score ≠ AI 可用**。IDC 机房的 IP 即使分数低，也可能因 IP 段属性触发挑战。分数只是门票，第 3 步的实测才是准绳。

### 8.2 出口分级（E1 / E2 / E3）

| 出口 | 用途 | 选择标准 | 成本 |
|---|---|---|---|
| **E1 主出口** = VPS 原生 IP | Google / YouTube / 日常 | 带宽大、延迟低 | 含在 VPS 内 |
| **E2 AI 出口** = 固定干净落地 | OpenAI / Anthropic / Gemini | **地区/ASN 固定、Fraud Score ≤20、实测解锁**；① 专用落地 VPS（首选）→ ② 合规静态 ISP/住宅代理（≈10Mbps，成本高）→ ③ WARP（兜底） | $0–$15/月 |
| **E3 兜底** = 商用解锁节点 | E2 失效时临时顶上 | 可用即可，不作长期依赖 | 按量 |

### 8.3 WARP 为什么只能兜底（重要修正）

| 观察 | 结果 | 来源 |
|---|---|---|
| OpenAI 对 `SNI(chatgpt.com) + 源 IP(WARP IPv4)` 做定向 TLS 拒绝，例：`104.28.213.40` 被拒 | ChatGPT 直接 4xx/5xx，换回 VPS 原生 IP 即恢复 | `[社区]` 2026-08 |
| WARP 出口采用就近 Cloudflare 接入点，地区会漂移 | 账号地区漂移 → 风控/challenge；Cloudflare 社区有香港 WARP 无法访问 ChatGPT 的报告 | `[社区]` |
| WARP 出口 IP 被大量用户共享 | 单 IP 信誉随他人行为波动 | `[推断]` |

所以：**E2 首选固定干净落地；WARP 只在 E2 不可用时临时顶上，并接受它随时可能被拒。** 这与 readme 的「AI 流量优先走 WARP」相反。

### 8.4 出口纪律（比换出口更省事）

- AI 出口的**国家/地区不要频繁变化**，减少切换；浏览器、终端、API 尽量共用同一出口。
- AI 出口**不跑 BT/大流量下载**，不与人共用账号。
- 固定用 v4 出站（`strategy: ipv4_only`），避免「计划走 v4、实际走 v6」导致出口 IP 与预期不符。
- 每周复测一次 IPQS + 解锁，记录趋势（分数上升通常是同段 IP 被人滥用）。

## 9. 稳定性与运维

### 9.1 传输层与系统层

- **TCP 侧**：`fq + bbr`（见 §4.4）；这是跨境代理的基础优化，丢包时仍能充分利用带宽。
- **QUIC 侧**：Brutal 由客户端带宽参数控制；服务端注意 `rmem_max/wmem_max`（§4.4）。
- **时间同步**：REALITY 握手依赖时间窗，NTP 异常会表现为「突然全部连不上」。
- **证书**：只有 Hysteria2 需要；自动续期 + 到期前 30 天告警。证书过期是 Hy2 最常见的失效原因 `[推断]`。

### 9.2 观测与告警

| 对象 | 看什么 | 频率 |
|---|---|---|
| 客户端 | Clash API 面板：连接走了哪个出站、哪个规则命中 | 实时 |
| 服务端 | 仅资源与流量（`vnstat`/`node_exporter`）；**不记录客户端 IP/访问域名**，缩小泄露面 | 实时 |
| 外部探针 | 每 5 分钟：TCP/443 握手、Hy2 UDP 端口可达、下载速度 | 每 5 分钟，失败 N 次告警 |
| IP 与解锁 | IPQS 分数 + ChatGPT 实测 | 每周 |

### 9.3 故障手册

| 现象 | 最可能的判定 | 动作 |
|---|---|---|
| 三端同时连不上 | 服务端进程挂了 / 证书过期 / IP 被封 | `systemctl status sing-box` → 看证书有效期 → 从国内 ping/端口探测 |
| REALITY 通、Hy2 不通 | UDP 被限速或阻断 | 换高位端口 + 端口跳跃 + 确认 obfs；或直接以 REALITY 为主 |
| Hy2 通、REALITY 不通 | TCP/443 被针对 | 换端口 / 换 `dest` 站点 / 换 `short_id` |
| 能连但 ChatGPT 报错或无限 challenge | AI 出口被风控 | 换 E2 出口；检查出口国家是否漂移；清 cookie 重登 |
| 一切正常但很慢 | 线路拥塞 / 超售 | 分时段测速；搬瓦工可迁移机房，或直接换机 |
| 国内站点变慢 | 分流规则失效或 DNS 误判 | 检查 rule_set 是否更新成功；确认 `sniff` 在前；核对规则顺序 |
| 突然全部失效且时间异常 | NTP/时区问题（REALITY） | `timedatectl` + 重启 `systemd-timesyncd` |

### 9.4 变更与备份

- 配置入私有 Git；每次变更前 `cp config.json config.json.bak` + `sing-box check -c`。
- 密钥/UUID/私钥与配置分离管理（`sops`/`age` 或 `chmod 600`）。
- 保留一份「已知可用」的快照，故障时先回滚再排查。

## 12. 风险登记

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
