客户端配置

在 macOS、Linux 或 Windows 上准备免密登录，目标是让 ssh 别名 直接进服务器，不再输密码。服务端加固在下一步，本页只做客户端侧。

目标

本机有一把 Ed25519 密钥，服务器上已安装对应公钥，~/.ssh/config 里有一条指向该服务器的别名，且用 BatchMode=yes 能免交互登录。全部动作幂等，可重复执行。

准备工作

  • 已知服务器地址与 SSH 端口
  • 当前能用密码或已有密钥登录一次，用于安装公钥
  • Windows 上使用系统自带 OpenSSH Client，脚本在 Git Bash 或 WSL 中执行

实施步骤

一条命令完成

bash bin/harden/client.sh --host 203.0.113.10 --port 4061 --alias vps-byte --install-server

--alias 是给这台服务器起的名字，之后用 ssh vps-byte 登录。不给时脚本先复用已有同地址块的名字，都没有才落到默认的 vps。脚本做四件事，每件都幂等：

动作细节
生成或复用密钥已有 ~/.ssh/id_ed25519 就用它，没有则生成 Ed25519，不设口令
安装公钥先查服务器上是否已存在同一把公钥，避免重复追加；只追加，不改动其他行
写 ~/.ssh/config同地址同端口已有块时复用它；--alias 与块名相同但地址、端口或密钥不同时，就地重写该块并备份为 config.bak
验证用 BatchMode=yes 连一次，失败即以非零退出

生成的配置

Host vps-byte
  HostName 203.0.113.10
  Port 4061
  User root
  IdentityFile /Users/你/.ssh/id_ed25519
  IdentitiesOnly yes

Host 后面就是服务器名字。多台机器建议各起一个能区分用途的名字，例如 vps-byte、vps-hk、test-box，不要都叫 vps：名字重复时后写的块会先被匹配到，改端口时容易改错机器。

IdentityFile 是绝对路径，脚本按本机实际 HOME 展开。手工改这段时不要换成 ~：OpenSSH 展开 ~ 用的是 passwd 里的家目录，与 HOME 环境变量无关，换用户执行会指向别处。

IdentitiesOnly yes 让客户端只尝试这一把密钥。服务器 MaxAuthTries 3 时，客户端若挨个试代理里的密钥，几次就会耗尽配额。

已有配置怎么复用

之前用 ssh-copy-id 或别的手册配过同一台服务器时，~/.ssh/config 里往往已有可用记录。脚本按地址与端口查找，能复用就不新写一份：

现状脚本行为
已有块指向同一地址与端口沿用该块的名字与 IdentityFile，不新建；公钥已在服务器上时不重复追加
要改名，地址端口不变写入新名字的块，旧块按 --prune 删除或给出提示
地址不变，端口变了用旧名字配 --alias 旧名字 重跑，就地改写该块的 Port，并备份 config.bak
指向同一地址的块有多条先提示，是否删除由你决定；--prune 直接删掉多余的那几条
脚本只删自己识别得到的重复块，条件是 HostName 与 Port 都相同；不同地址的块一律不碰。删除前都会备份 ~/.ssh/config.bak。

手工做法

手工做完后同样建议补一条 Host 块，否则每次都要写地址与端口。已经手工配过的，用 --check 看脚本能否复用：

ssh-keygen -t ed25519 -C "laptop"
ssh-copy-id -p 4061 root@203.0.113.10      # Windows 无 ssh-copy-id，用下面的写法
type %USERPROFILE%\.ssh\id_ed25519.pub | ssh -p 4061 root@203.0.113.10 "cat >> ~/.ssh/authorized_keys"
ssh -o BatchMode=yes -p 4061 root@203.0.113.10 true   # 这一步成功再继续
不要在密钥登录验证通过之前关闭密码登录。顺序颠倒会同时失去两种登录方式，此时只能走云控制台。

检查与验证

bash bin/harden/client.sh --check      # 报告目标、将沿用的名字与密钥、已有块、能否登录
ssh -o BatchMode=yes 你的别名 true && echo 公钥OK

两条都通过才能进入服务端加固。第一条只读，不写任何文件。

下一步

进入服务端加固。顺序不能颠倒：服务端脚本会检查当前会话是否经公钥认证，读不到证据就拒绝执行。

回退与卸载

# 预览要写什么，不改任何文件
bash bin/harden/client.sh --host 203.0.113.10 --port 4061 --alias vps-byte --dry-run

# 改名并清理指向同一地址的旧块
bash bin/harden/client.sh --host 203.0.113.10 --port 4061 --alias vps-byte --prune --yes

# 撤销：删除服务器上的公钥行，并移除本地 Host 块
ssh 你的别名 "sed -i '/你的密钥指纹或注释$/d' ~/.ssh/authorized_keys"

~/.ssh/config 被改写前会自动备份为 config.bak，需要恢复时直接覆盖回来。

命令手册

bash bin/harden/client.sh --host 地址 --port 端口 --alias 名字 --install-server
bash bin/harden/client.sh --host 地址 --port 端口 --check
bash bin/harden/client.sh --host 地址 --port 端口 --alias 名字 --dry-run
bash bin/harden/client.sh --host 地址 --port 端口 --alias 名字 --prune --yes

参数说明

参数默认说明
--host必填服务器地址
--port读取 ~/.ssh/config 同名块，否则 22SSH 端口
--userroot登录用户
--alias复用同地址块，否则 vps写进 ~/.ssh/config 的名字
--install-server关把本机公钥追加到服务器的 authorized_keys
--check关只报告状态，不写文件
--dry-run关预览将写入的内容
--prune关删除指向同一地址与端口的重复块
平台OpenSSH 来源注意
macOS系统自带钥匙串可用 ssh-add --apple-use-keychain，但本方案不需要保管口令
Linux发行版自带无额外依赖
Windows 10/11系统自带 OpenSSH Client路径为 %USERPROFILE%\.ssh，脚本在 Git Bash 或 WSL 中执行

密钥的三个决定：算法用 Ed25519，密钥短、签名快、无参数需要挑选；不设口令，免密登录的前提就是密钥无口令，文件权限设为 600，需要额外保护时用系统登录密码与全盘加密，而不是给密钥加口令后再依赖 ssh-agent；一台设备一把密钥，吊销时删掉服务器上对应那一行即可，不影响其他设备。

常见错误与排查

现象原因处理
--check 显示无法登录公钥未安装，或端口、用户不符补 --install-server 重跑；确认 --port 与服务端一致
公钥重复追加了多次手工 ssh-copy-id 与脚本各装了一次服务器上合并 authorized_keys 里的重复行，或 bin/deploy/device.sh 之外单独清理
同一个别名连到了别的机器多台服务器共用一个 Host 名字用 --prune 清理重复块，每台机器各起一个名字
换用户执行后密钥路径失效配置里写了 ~ 而非绝对路径改回绝对路径，或重新用脚本生成
