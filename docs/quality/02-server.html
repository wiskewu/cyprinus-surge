服务端加固

在服务器上执行加固：关闭密码登录、限制认证尝试、启用速率限制与封禁。本页覆盖执行顺序、写入的配置、公钥清点与回滚。

目标

加固后服务端只接受公钥认证，root 只能用密钥，端口上有限速规则，失败尝试由 fail2ban 封禁；同时保证任何一步失败都不会让 SSH 变得不可用。

准备工作

  • 已按客户端配置装好公钥，并且用密钥成功登录过一次
  • 当前会话保持打开，另开一个终端用于验证
  • 云控制台的 VNC 或串口可用，作为最终兜底

先看现状，端口取自 sshd -T，不假设是 22：

sudo bash bin/harden/harden.sh --check
sshd 端口          : 4061
密码登录           : yes
root 登录          : yes
键盘交互           : no
MaxAuthTries       : 6
MaxStartups        : 10:30:100
可用公钥数         : 1
重复公钥           : 0
本次会话公钥登录   : 是
加固片段           : 不存在
本次会话公钥登录 为「否」时不要继续。脚本依赖这一项判断是否可以安全关闭密码登录。

实施步骤

sudo bash bin/harden/harden.sh
sudo bash bin/harden/harden.sh --whitelist 198.51.100.20   # 顺手把常用出口加入 fail2ban 白名单

脚本按下列顺序执行，任何一步失败都不会让 SSH 不可用：

  1. 检查 authorized_keys 至少有可用公钥，并确认当前会话经公钥认证。
  2. 备份 sshd_config、drop-in 目录与 ufw status 到 /root/ssh-hardening/<时间戳>。
  3. 写 /etc/ssh/sshd_config.d/99-ssh-hardening.conf。若有排序更靠前的文件写了同一关键字，就地改掉，因为 sshd 取第一个出现的值。
  4. sshd -t 校验，不通过则删除新建片段并且不 reload。
  5. systemctl reload ssh，再回读 sshd -T 确认生效。
  6. ufw limit <端口>/tcp，并删除同端口的 allow 规则。
  7. 写 fail2ban 的 sshd jail 与白名单，reload 并确认运行。
只 reload，不 restart。reload 保留现有会话，restart 会短暂拒绝新连接，脚本不重启 sshd。

已装公钥的清点与去重

重复执行 ssh-copy-id 或从多台机器追加公钥，会让同一把公钥在 authorized_keys 里出现多次。脚本不会自动删，先看清单再决定：

sudo bash bin/harden/harden.sh --keys      # 指纹、注释、文件:行号，并给出重复数
sudo bash bin/harden/harden.sh --dedupe    # 同一把公钥只保留第一次出现，改动前备份为 .bak
文件  指纹与信息：
  SHA256:bITvBsN003zJLsvkczTKO5IaIPw3fa3sjZuBqNjWzyk  laptop  /root/.ssh/authorized_keys:2
  SHA256:rwjRtPuv/eKMqaOiFREHT3+uKj+8VltZvP9P4egDMuI  phone   /root/.ssh/authorized_keys:3
  SHA256:bITvBsN003zJLsvkczTKO5IaIPw3fa3sjZuBqNjWzyk  laptop  /root/.ssh/authorized_keys:4

重复公钥：1 把（sudo bash bin/harden/harden.sh --dedupe 可删掉多余行）

应用加固时若检测到重复，脚本会先问一次要不要去重；选不去重也能继续，只是回滚与吊销时容易漏。

吊销某台设备的登录权：在 --keys 里找到那行的指纹与行号，删掉对应行即可。--dedupe 只删同一把公钥的重复行，不会删掉唯一的公钥，因此不会把人关在门外。

检查与验证

sshd -T | grep -iE '^(passwordauthentication|permitrootlogin|maxauthtries|maxstartups)'
ufw status numbered | grep 4061
fail2ban-client status sshd

三条判据：passwordauthentication 为 no、permitrootlogin 为 without-password 或 prohibit-password、maxauthtries 为 3。ufw 里该端口应显示 LIMIT，fail2ban 的 sshd jail 应为运行中。完整验收在客户端侧执行，见验收与排障。

下一步

到验收与排障做独立验收。要调整默认值或评估额外加固项，见参数与取舍。

回退与卸载

sudo bash bin/harden/harden.sh --uninstall

删除加固片段，从 /root/ssh-hardening/latest 还原被就地改写的文件，恢复 PasswordAuthentication yes 与 ufw allow，然后 reload。回滚后应立刻用密码登录验证一次，再关闭当前会话。

回滚会重新打开密码登录。只在确认能登录的前提下使用，并在处理完问题后再次执行加固。

参数说明

加固片段写入的九项值：

项值作用
PasswordAuthenticationno关闭密码认证，消除爆破面
KbdInteractiveAuthenticationno键盘交互同样能送密码，一并关闭
PermitRootLoginprohibit-passwordroot 只能用密钥
MaxAuthTries3单连接最多三次认证机会
LoginGraceTime20未认证连接 20 秒断开
MaxStartups5:30:10未认证并发超过 5 个开始随机丢弃，达到 10 个全拒
ClientAliveInterval300空闲会话保活探测
ClientAliveCountMax2连续两次无响应即断开，空闲约 10 分钟释放
X11Forwardingno不需要图形转发

MaxStartups 与 LoginGraceTime 在小内存机器上收益明确：每个未认证连接都占一个 sshd 进程。空闲会话 10 分钟断开，长任务要用 tmux 或 nohup。--whitelist 写入 fail2ban 的 ignoreip，可重复给多个地址，默认只含回环地址。

常见错误与排查

现象原因处理
脚本拒绝执行当前会话未通过公钥认证先用新终端验证密钥登录，再执行
回读后仍是旧值排序更靠前的文件写了同一关键字grep -rn PasswordAuthentication /etc/ssh/sshd_config*，改靠前那一行后 reload
登录被拒且没被 fail2ban 封禁该来源触发了 ufw limit等 30 秒重试，或把固定出口加进 --whitelist
公钥数比预期多重复追加--keys 看清楚再用 --dedupe
