4 · 验收与运维

六条能当场跑出来的验收，加上日常使用与长期维护。

验收

#检查怎么做通过
1敲门有效客户端 fwknop -n server1；服务器上 iptables -S FWKNOP_INPUT | wc -l≥1；ACCESS_TIMEOUT 秒后变回 0
2端口不可达从另一台外网机器 nmap -Pn -p22 <IP>filtered（不是 closed）
3用起来无感ssh / scp / rsync / VS Code Remote-SSH都能直连，不用逐个工具配
4重放无效服务端 tcpreplay -i <iface> /tmp/spa.pcap规则数不增加
5单台可吊销从密钥包去掉一台，重跑服务端该设备敲不开；其余照常
6ufw 看不到临时规则ufw status没有（fwknopd 直接动 iptables）

第 4 条要先抓包：sudo tcpdump -i any udp port 62201 -w /tmp/spa.pcap，再在客户端敲一次。

第 1 条过不了，就不能跑 --close-ssh。收口后唯一的门就是 FWKNOP_INPUT，而脚本删公网规则前只探测端口，不验证敲门。日志里反复出现 Non-corresponding HMAC for this stanza 时，先查两端 HMAC_DIGEST_TYPE 是否一致，见第 5 页速查表。

状态

sudo bash 10-server.sh --status
bash 20-client.sh --keys ~/laptop.env --status

日常使用

ssh server1                          # 透明，不用管敲门
fwknop -n server1                    # 手动敲一次
fwknop -n server1 --fw-timeout 300    # 开窗久一点（被 MAX_FW_TIMEOUT 封顶）
fwknop -n server1 -v                 # 打印它到底发到哪儿了

长会话

窗口到期撤的是新连接许可，已建立的会话不受影响。但端口转发、tail -f 这类要调大 ACCESS_TIMEOUT 后重跑服务端：

# 编辑 spa-keys.env 里的 ACCESS_TIMEOUT
sudo bash 10-server.sh --keys spa-keys.env

加设备

bash 00-gen-keys.sh --clients "laptop phone tablet" --force
# 服务器重跑 10-server.sh；新设备拿 clients/tablet.env 跑 20-client.sh

--force 会丢旧密钥。想平滑迁移就把旧条目从 spa-keys.env 里抄出来留着，确认都迁到新包后再删。

备份

对象丢了会怎样
spa-keys.env所有客户端一起失效，需全量重发
clients/<名字>.env该设备要重配
/etc/fwknop/*.conf不丢：脚本能重建
~/.ssh/config 托管块不丢：重跑 20-client.sh

值得备份的只有密钥包和SSH 私钥。放两份：一份在密码管理器，一份在 sops/age 加密的私有仓库。别进 git（哪怕私有），别贴进聊天窗口。

批量管理

# group_vars/all/vars.yml
ansible_ssh_common_args: >-
  -o ProxyCommand="sh -c 'fwknop -n {{ inventory_hostname }} >/dev/null 2>&1; sleep 2; exec nc %h %p'"
  • 用 inventory_hostname 不是 %h：%h 是 ansible_host 解析出来的值（可能是 IP），stanza 是按 inventory 主机名命名的
  • 新机器没装 fwknop 时敲门失败但 nc 会直连（那时 22 还开着），安装前后同一条配置都成立
  • 配 ControlPersist 后每次 play 只敲一次
两个角色互相覆盖：一个负责「加公网 SSH 规则」、一个负责「删」，每次 Ansible 都绿但端口又开了。修法不是调顺序，是让两边读同一个变量——谁最后跑结果都一样：
linux_base_ssh_public: "{{ not (fwknop_enabled | default(false) | bool) }}"
