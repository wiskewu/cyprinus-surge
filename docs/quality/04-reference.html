参数与取舍

参考页：脚本参数的默认值与副作用、ufw limit 的实际行为、fail2ban 规则，以及可选双因子与本手册明确放弃的加固项。

目标

需要修改默认值、评估额外加固，或解释某条规则为何如此时，在这一页找到事实依据，不必回头读脚本。

参数说明

脚本参数默认副作用
bin/harden/harden.sh--check不加则为应用无，只读
--keys否无，只列出 authorized_keys 的指纹与重复项
--dedupe否删除重复公钥行，改动前备份 authorized_keys.bak
--uninstall否恢复密码登录与 ufw allow
--whitelist IP[,IP]仅 127.0.0.1 与 ::1写入 fail2ban 的 ignoreip
--force否跳过「当前会话必须公钥登录」的检查
bin/harden/client.sh--host必填无
--port先取同地址块的 Port，否则 22无
--userroot无
--alias复用同地址块的名字，都没有时 vps写入或重写 ~/.ssh/config 的 Host 块，重写前备份 config.bak
--install-server / --prune / --dry-run / --yes否分别追加公钥、删除重复块、只预览、不提问
bin/harden/audit.sh--alias 或 --host必填其一无，只读

三个脚本都幂等，重复执行只补齐缺失的部分。

ufw limit 的行为

项值
限制粒度按来源 IP，对新建连接计数
阈值30 秒内 6 次，超出即丢弃新连接
恢复方式等待窗口滑过后自动恢复，不需要人工干预
副作用批量脚本、并发终端、验收脚本都可能触发；bin/harden/audit.sh 因此把远程检查合并为一次连接

并发需求高于该阈值时，把 ufw limit 换成 ufw allow 并保留 fail2ban，封禁由 fail2ban 承担。

fail2ban 规则

[DEFAULT]
ignoreip = 127.0.0.1/8 ::1
bantime = 1h
findtime = 10m
maxretry = 4

[sshd]
enabled = true
键含义
bantime封禁时长
findtime统计窗口
maxretry窗口内失败次数阈值
ignoreip永不封禁的地址，用于固定出口

实施步骤

可选：双因子

TOTP 能在密钥泄露后仍然拦住登录，代价是必须打开 KbdInteractiveAuthentication，而默认方案刻意关闭了它。

项说明
依赖libpam-google-authenticator，Debian 13 源内有
配置AuthenticationMethods publickey,keyboard-interactive:pam，配合 PAM 里的 pam_google_authenticator.so
风险手机丢失、时钟漂移、PAM 顺序写错都会导致完全无法登录
前置先保存恢复码，并确认云控制台可用

启用顺序：先在现有会话里改配置，再用另一个终端完整验证一次密钥加动态码登录，最后才关闭验证会话。

检查与验证

ufw status numbered | grep LIMIT
fail2ban-client status sshd
fail2ban-client get sshd ignoreip

三条分别确认：该端口只有 LIMIT 规则、jail 在运行、白名单内容与预期一致。

sudo bash bin/harden/harden.sh --uninstall  # 或整体回滚，恢复密码登录

常见错误与排查

不建议启用

项原因
authorized_keys 的 from="IP"出口 IP 变化即失效，与免密登录的便利性直接冲突
CrowdSec 替代 fail2ban多两个常驻进程，默认向社区 API 上报攻击者信息
AIDE 每日基线比对每次升级都改 /usr/bin，告警噪音高于收益；按需 dpkg --verify 更实用
全量 auditd小盘上日志增长快，规则需要长期维护
SPA 单包授权依赖 UDP 单包，链路或网络策略阻断 UDP 时完全不可用

常见误配

现象原因处理
白名单里的地址换了出口后仍被拦出口 IP 会变化的网络，写进 ignoreip 的那条很快失效删掉该白名单项；改用密钥登录本来也不产生失败尝试
并发终端偶尔被限速ufw limit 按来源计数提高并发需求时换成 ufw allow，封禁交给 fail2ban
开启双因子后彻底登不进去PAM 顺序写错或时钟漂移走云控制台还原配置，再按启用顺序重做
