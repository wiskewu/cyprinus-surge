3 · 多客户端密钥

这是本手册相对原始方案的主要补充：一台设备一把密钥，丢一台就吊销一台，不用动其他任何设备。

原理：stanza 是加法

access.conf 支持多个 stanza，每个有自己的密钥。fwknopd 收到包后逐个 stanza 试解密，只有对上的那个能开规则——任一步失败就跳到下一个 stanza 继续（server/incoming_spa.c 里的 incoming_spa()，while(acc) 循环中每一处失败分支都是 acc = acc->next; continue;）。

所以所有 stanza 都可以写 SOURCE ANY，靠密钥而不是靠来源地址区分设备。这很重要：客户端会换 IP（家宽、移动网络、公司网络），按 IP 区分的模型在漫游时直接失效。

两种模式

每设备独立密钥 推荐全部共用一组 简单
access.conf每台设备一个 stanza只有一个 stanza
客户端各拿一份密钥包共用同一份
吊销一台删掉一个 stanza，其余不受影响全换，所有设备重配
轮换成本可以分批发，先加新的再删旧的一次改一处，但影响面最大
密钥泄露影响面一台设备所有设备
生成命令--clients "laptop phone"--shared

代价只是多一个密钥包文件，脚本已经替你做了：00-gen-keys.sh --clients 会产出服务端一份 + 每台客户端一份，每份里只有它自己的那对密钥。

不要把所有客户端的密钥包发到每一台机器上。客户端只需要自己的那一份。需要管理全部密钥时用服务端那份 spa-keys.env，而且它应该待在密码管理器或 sops/age 加密的仓库里，不该躺在某个人的家目录。

密钥包格式

生成的服务端包长这样：

SPA_PORT=62201
SSH_PORT=22
ACCESS_TIMEOUT=120
MAX_FW_TIMEOUT=300
HOSTS="server1=203.0.113.10 server2=198.51.100.7"
CLIENTS="laptop=<KEY_BASE64>:<HMAC_KEY_BASE64> phone=<KEY_BASE64>:<HMAC_KEY_BASE64>"

每客户端的包把同一行换成自己的名字，并多一行 CLIENT_NAME：

HOSTS="server1=203.0.113.10 server2=198.51.100.7"
CLIENT_NAME=laptop
CLIENTS="laptop=<KEY_BASE64>:<HMAC_KEY_BASE64>"

共用的模式则是一行 SHARED=<KEY>:<HMAC>。

格式上的一个坑：每客户端的键值必须放在一行带引号的 CLIENTS="..." 里，不能写成 CLIENT laptop=...。后者不是合法的 shell 赋值，脚本 source 这个文件时会直接报 CLIENT: command not found。

渲染出来的 access.conf

每台设备一个 stanza，只有密钥不同：

# --- laptop ---
SOURCE ANY;
OPEN_PORTS tcp/22;
FW_ACCESS_TIMEOUT 120;
MAX_FW_TIMEOUT 300;
KEY_BASE64        <laptop 的加密密钥>;
HMAC_KEY_BASE64   <laptop 的 HMAC 密钥>;

# --- phone ---
SOURCE ANY;
OPEN_PORTS tcp/22;
FW_ACCESS_TIMEOUT 120;
MAX_FW_TIMEOUT 300;
KEY_BASE64        <phone 的加密密钥>;
HMAC_KEY_BASE64   <phone 的 HMAC 密钥>;

10-server.sh 渲染后会自检：渲染出的 stanza 数必须等于密钥包里的密钥组数，对不上就退出，不会写一个半成品上去。

几个参数的含义

OPEN_PORTS
收到有效包之后打开哪些端口。它由服务端说了算。
FW_ACCESS_TIMEOUT
规则保留多少秒。不设则默认 30 秒。
MAX_FW_TIMEOUT
封顶：客户端用 --fw-timeout 也拿不到超过这个值的窗口。不设则默认 300 秒。

没有开启 PERMIT_CLIENT_PORTS，所以客户端在 ACCESS 里写什么都不能改变服务端放行的端口。

轮换与吊销

吊销一台

# 从密钥包里去掉那台（或用 --clients 只留其余的 --force 重新生成）
sudo bash 10-server.sh --keys spa-keys.env

那台设备立刻敲不开，其余设备完全不受影响。别忘了顺手把设备上的密钥包删掉——服务端拒绝对它来说只是「连不上」，本地那份文件仍然是有效的凭据。

全量轮换

bash 00-gen-keys.sh --hosts "server1=203.0.113.10" --clients "laptop phone" --force
# 分发新的 spa-keys.env 与 clients/*.env，逐台重跑 10-server.sh / 20-client.sh
# 确认都迁完了，再从旧包里删掉旧条目重跑一次服务端

两套 stanza 可以共存，所以能先加新的、确认都迁走了再删旧的。

生成脚本

bash 00-gen-keys.sh --out spa-keys.env \
  --hosts "server1=203.0.113.10 server2=198.51.100.7" \
  --clients "laptop phone"
参数作用
--hosts "h1=ip h2=host"这批密钥管哪些主机。写进客户端配置，按名字分段
--clients "laptop phone"每台客户端一个独立密钥，可单独吊销
--shared只生成一组共用密钥（与 --clients 二选一）
--force覆盖已存在的密钥包（旧的立即失效）
--out FILE输出路径，默认 spa-keys.env

密钥用 openssl rand -base64 32 生成，格式与 fwknop --key-gen 相同（fwknop 会自己 base64 解码再派生，任何长度的 base64 字符串都合法）。脚本跑完会做一次自检：把密钥包 source 回去，逐个设备取密钥，格式不对就退出。

脚本全文
#!/usr/bin/env bash
# 00-gen-keys.sh —— 生成 SPA 密钥包。
#   产出两份东西：
#     spa-keys.env       服务端用（含全部客户端密钥）
#     clients/<name>.env 每台客户端一份（只含自己的那对密钥）
#   密钥格式与 `fwknop --key-gen` 一致：KEY_BASE64 + HMAC_KEY_BASE64。
set -euo pipefail
SELF_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
# shellcheck source=lib.sh
. "$SELF_DIR/lib.sh"
need_cmd openssl

OUT="spa-keys.env"
CLIENTS=""
HOSTS=""
SHARED=0
FORCE=0

usage() {
  cat <<'EOF'
用法：bash 00-gen-keys.sh [选项]

  --out FILE            密钥包路径（默认 spa-keys.env）
  --hosts "h1=ip h2=host"  这批密钥管哪些主机（写进客户端配置，按名字分段）
  --clients "laptop phone" 每台客户端一个独立密钥，可单独吊销（推荐）
  --shared              只生成一组共用密钥，所有客户端相同（简单，但吊销一个要全换）
  --force               覆盖已存在的密钥包
  -h, --help            显示帮助

例：
  bash 00-gen-keys.sh --hosts "server1=203.0.113.10" --clients "laptop phone"
EOF
}

while [ $# -gt 0 ]; do
  case "$1" in
    --out) shift; OUT="${1:?--out 需要参数}" ;;
    --out=*) OUT="${1#*=}" ;;
    --hosts) shift; HOSTS="${1:?--hosts 需要参数}" ;;
    --hosts=*) HOSTS="${1#*=}" ;;
    --clients) shift; CLIENTS="${1:?--clients 需要参数}" ;;
    --clients=*) CLIENTS="${1#*=}" ;;
    --shared) SHARED=1 ;;
    --force) FORCE=1 ;;
    -h|--help) usage; exit 0 ;;
    *) die "未知参数：$1（--help 看用法）" ;;
  esac
  shift
done

[ "$SHARED" = 1 ] || [ -n "$CLIENTS" ] || { usage; die "--clients 和 --shared 至少给一个"; }
[ "$SHARED" = 1 ] && [ -n "$CLIENTS" ] && die "--clients 与 --shared 二选一"
CLIENTS_ARG="$CLIENTS"   # 固定下来：load_env 之后 CLIENTS 会被密钥包里的同名变量覆盖

if [ -e "$OUT" ] && [ "$FORCE" != 1 ]; then
  die "$OUT 已存在。确认要覆盖（旧的密钥会失效）就加 --force"
fi

umask 077
OUT_DIR="$(dirname "$OUT")"
mkdir -p "$OUT_DIR/clients"

# --- 参数校验：主机名格式和客户端名字都要能安全进 grep/sed ---
if [ -n "$HOSTS" ]; then
  for h in $HOSTS; do
    case "$h" in
      *=?*) valid_name "${h%%=*}" || die "主机名不合法：$h（只允许字母数字 . _ -）" ;;
      *) die "主机条目要写成 name=地址：$h" ;;
    esac
  done
fi
if [ -n "$CLIENTS_ARG" ]; then
  for c in $CLIENTS_ARG; do
    valid_name "$c" || die "客户端名不合法：$c（只允许字母数字 . _ -）"
  done
fi

STAMP="$(date -u +%FT%TZ)"
HEADER="# ssh-spa 密钥包 · 生成于 $STAMP
# chmod 600：含可直接开你服务器的口令，不要提交进 git、不要贴进聊天窗口。
# 用法：拷给服务端 → 10-server.sh --keys；拷给客户端 → 20-client.sh --keys。
"

write_bundle() {
  # $1=输出文件 $2=该文件专属的键值行（SHARED=… / CLIENTS="…"）
  cat > "$1" <<EOF
$HEADER
SPA_PORT=62201
SSH_PORT=22
ACCESS_TIMEOUT=120
MAX_FW_TIMEOUT=300
HOSTS="$HOSTS"
$2
EOF
  chmod 600 "$1"
}

log "生成密钥"
if [ "$SHARED" = 1 ]; then
  pair="$(gen_key):$(gen_key)"   # 服务端包和客户端包必须用同一对
  write_bundle "$OUT" "SHARED=$pair"
  write_bundle "$OUT_DIR/clients/shared.env" "SHARED=$pair"
  log "共用密钥 → $OUT 与 $OUT_DIR/clients/shared.env（两份内容一致）"
else
  ENTRIES=""
  for c in $CLIENTS_ARG; do
    pair="$(gen_key):$(gen_key)"   # 一台客户端一对密钥，服务端包和客户端包必须用同一对
    ENTRIES="${ENTRIES:+$ENTRIES }$c=$pair"
    write_bundle "$OUT_DIR/clients/$c.env" "CLIENT_NAME=$c
CLIENTS=\"$c=$pair\""
    log "客户端 $c → $OUT_DIR/clients/$c.env"
  done
  write_bundle "$OUT" "CLIENTS=\"$ENTRIES\""
  log "服务端包 → $OUT"
fi

# --- 自检：写出来的文件要能被 source 回去，密钥条数要对得上 ---
load_env "$OUT"
if [ -n "$CLIENTS_ARG" ]; then
  want="$(host_count "$CLIENTS_ARG")"
  got="$(host_count "${CLIENTS:-}")"
  [ "$got" = "$want" ] || die "自检失败：$OUT 里 $got 条客户端密钥，期望 $want 条"
  for c in $CLIENTS_ARG; do
    pair="$(spa_keys_for "$OUT" "$c")"
    case "$pair" in
      *:*) [ -n "${pair%%:*}" ] && [ -n "${pair##*:}" ] || die "自检失败：客户端 $c 密钥对不完整" ;;
      *) die "自检失败：客户端 $c 的密钥对格式不对" ;;
    esac
  done
else
  spa_keys_for "$OUT" >/dev/null || die "自检失败：SHARED 取不到"
fi

log "自检通过"
cat <<EOF

下一步：
  1) 服务端：scp $OUT root@<服务器>:/root/ && ssh root@<服务器> 'bash 10-server.sh --keys /root/$(basename "$OUT")'
     （先别加 --close-ssh，见 README「避免把自己锁在门外」）
  2) 客户端：scp $OUT_DIR/clients/<名字>.env <机器>:~/ && 在那台机器上 bash 20-client.sh --keys ~/<名字>.env
     （每台机器只需要自己那一份，不需要 spa-keys.env）
EOF
