5 · 验收与运维

六条可以当场跑出来的验收条件，外加日常使用与长期维护。

验收清单

#检查怎么做通过标准
1敲门有效客户端 fwknop -n server1；同时在服务器上 iptables -S FWKNOP_INPUT | wc -l规则数 ≥1；ACCESS_TIMEOUT 秒后自己变回 0
2端口对外不可达从另一台外网机器：nmap -Pn -p22 <服务器IP>filtered（不是 closed）
3用起来无感ssh server1，以及 scp / rsync / sftp / VS Code Remote-SSH都能直连，不需要为每个工具单独配置
4重放无效服务端 tcpreplay -i <iface> /tmp/spa.pcap（包由第 1 步抓）规则数不增加，日志里有 replay 丢弃记录
5单台可吊销从 spa-keys.env 去掉一台，重跑服务端该设备敲不开；其余设备照常
6不依赖 ufw 可见性ufw status看不到 SPA 临时规则（fwknopd 直接动 iptables）

抓包用于第 4 条：sudo tcpdump -i any udp port 62201 -w /tmp/spa.pcap，先在客户端敲一次。

状态查看

sudo bash 10-server.sh --status
bash 20-client.sh --keys ~/laptop.env --status

服务端会打印 fwknopd 是否 active、跳转规则在不在 INPUT 第 1 位、当前有几条临时规则、ufw 里 22 与 62201 的状态。客户端会打印 ~/.fwknoprc 有哪些 stanza、托管块在不在。

日常使用

ssh server1                          # 透明，不用管敲门
scp file server1:/tmp/                # 走同一条 ProxyCommand
fwknop -n server1                    # 手动敲一次（调防火墙时有用）
fwknop -n server1 --fw-timeout 300    # 开窗久一点（被服务端 MAX_FW_TIMEOUT 封顶）
fwknop -n server1 -v                 # 打印它到底发到哪儿了

要挂长时间会话

窗口到期撤销的是新连接的许可，已建立的会话不受影响。但 ssh -t、端口转发、tail -f 这类场景你多半希望时间更宽裕——调大 ACCESS_TIMEOUT 后重跑服务端脚本：

# 编辑 spa-keys.env 里的 ACCESS_TIMEOUT
sudo bash 10-server.sh --keys spa-keys.env

多台设备

每台机器只需要自己的 clients/<名字>.env，跑一次 20-client.sh 即可。新增设备：

bash 00-gen-keys.sh --clients "laptop phone tablet" --force
# 服务端包重跑 10-server.sh；新设备拿 clients/tablet.env 跑 20-client.sh

密钥全换时让新旧 stanza 共存一段时间：--force 会丢掉旧密钥，所以先把旧的那几条从 spa-keys.env 里抄出来留着，确认所有设备都迁到新包之后再删。

备份

对象在哪丢了会怎样
spa-keys.env管理机（密码管理器 / 加密仓库）所有客户端一起失效，需要全量重发
clients/<名字>.env对应设备上（也可以只留在管理机）该设备需要重配
/etc/fwknop/access.conf服务器 /etc/fwknop/不丢：spa-keys.env 能完整重建它
/etc/fwknop/fwknopd.conf同上（.orig 是包自带版本）不丢：10-server.sh 能重建
~/.ssh/config 托管块每台设备不丢：重跑 20-client.sh

值得备份的只有密钥包和SSH 私钥。服务器上那两个配置文件都是脚本的输出，丢了能重建。

密钥卫生

  • chmod 600 是脚本自动做的，但它只是权限，不是保护
  • 不要进 git（哪怕是私有库），不要贴进聊天窗口，不要放进截图
  • 存两份：一份在密码管理器，一份在 sops/age 加密的私有仓库
  • 怀疑泄露时按「全量轮换」处理，不要试图判断「会不会被发现」
轮换会让所有正在使用的会话之外的东西失效。先在 tailnet 或 VNC 上留一条通路，再动密钥。

批量管理

单机手动跑没问题；机器多了就把敲门接进 SSH 客户端本身。

# group_vars/all/vars.yml
ansible_ssh_common_args: >-
  -o ProxyCommand="sh -c 'fwknop -n {{ inventory_hostname }} >/dev/null 2>&1; sleep 2; exec nc %h %p'"
  • 用 inventory_hostname 而不是 %h：%h 是 ansible_host 解析出来的值（可能是 IP），而 ~/.fwknoprc 的 stanza 是按 inventory 主机名命名的
  • 新机器还没装 fwknop 时敲门会失败，但 nc 会直连（那时 22 还开着），同一条配置在安装前后都成立
  • 配 ControlPersist 后每次 play 只敲一次，不是每个 task 都敲
一个真实的坑：两个角色互相覆盖。一个角色负责「加公网 SSH 规则」、另一个负责「删」，结果每次 Ansible 都绿，但端口又开了。根治办法不是调 role 顺序，是让两边读同一个变量：
# base role 的默认值
ssh_public: "{{ not (fwknop_enabled | default(false) | bool) }}"
谁最后跑结果都一样。
