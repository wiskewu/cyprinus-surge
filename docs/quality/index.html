SSH 加固

主读者：维护单台 VPS 的运维者。本页说明为什么采用「仅公钥登录」这条路线，以及它在本环境里解决了什么问题、放弃了什么。操作步骤见 服务端加固 与 客户端配置。

结论

管理入口收敛为一条路径：公钥认证的 SSH。密码登录关闭，root 只接受密钥，端口加速率限制，失败尝试由 fail2ban 封禁。客户端使用系统自带 OpenSSH，不安装任何第三方组件，不分发证书。

为什么不用 SPA

单包授权（SPA）能把端口从扫描结果里藏起来，代价是每台客户端都要跑一个专用程序。实测两条都走不通：

路线实测结论
fwknopWindows 没有官方构建，收口后那台机器无法登录；服务端 62201/udp 长期对外
WireGuard 管理内网服务端在受控环境下可用，但当前宽带对目标地址的 UDP 全端口丢弃，握手都发不出去；换端口、停代理软件均无效

两条路线的共同前提是「客户端能主动发包到服务器的某个非 TCP 端口」。当这个前提不成立时，再精巧的授权协议也无法落地。相比之下，SSH 走 TCP，而 TCP 在该环境下正常。

放弃了什么

  • 端口对扫描器可见。代价用三层补偿：仅公钥、速率限制、失败封禁。
  • 不需要分发证书或密钥文件。客户端只做一次 ssh-keygen 与一次公钥安装。
  • 不引入常驻守护进程与内核模块，10 亿字节级内存的机器上零额外负担。

四步

#在哪台机器做什么命令
1客户端生成或复用 Ed25519 密钥bash ssh-client.sh --host <地址> --port <端口> --install-server
2客户端验证密钥能登录ssh -o BatchMode=yes <别名> true
3服务器关密码登录、加速率限制与封禁sudo bash ssh-server.sh
4客户端独立验收bash ssh-audit.sh --alias <别名>
第 3 步之前必须完成第 2 步。脚本会检查当前会话是否经公钥认证，读不到证据就拒绝执行。这是为了防止把「密钥不可用」和「密码已关闭」同时成立。
