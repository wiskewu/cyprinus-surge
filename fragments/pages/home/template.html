022026 年的三个关键前提（相对原稿的修正）

这三条决定了后面所有取舍，先看它们。

前提一：UDP/QUIC 出境被大范围干扰 研究社区

GFW 自 2024-04 起可解密 QUIC Initial 并做 SNI 过滤；2026-04 起社区报告全国性限制 UDP/443 出境，电信骨干网尤为明显。

结论：Hysteria2 不再默认做主入口，需叠加 obfs salamander + 端口跳跃；REALITY（TCP/443）成为默认主入口，最终以实测为准。

前提二：WARP 出口不能当 AI 主出口 社区

OpenAI 对 SNI(chatgpt.com) + 源 IP(WARP IPv4) 做过定向 TLS 拒绝（例：104.28.x.x）；WARP 出口地区还会漂移，导致账号地区跳变触发风控。

结论：AI 出口第一原则是「固定、干净、地区稳定」，WARP 只做零成本兜底。

前提三：sing-box 破坏性变更 官方

1.12 移除 GeoIP/GeoSite；1.13 移除 WireGuard 出站（改用 endpoints）；1.14 改 DNS 规则写法（直接写 server，不再写 action: route）。

结论：网上绝大多数老教程的配置在 1.14 上起不来。本方案所有配置按 1.14.x 编写，并用 sing-box check 校验后才上线。

不做的承诺：自建不等于「不会被封」。本方案做的是概率工程，把入口抗封锁、出口纯净度、全平台分流拆成三层，任一层失效都能单独替换，而不是把所有需求压在一台机器的单一 IP 上。

03总体架构

从左到右是一条完整的数据路径：客户端内完成分流，入口层负责「连得上」，出口层负责「被信任」。AI 流量从一开始就被分流到独立出口。

入口层（抗封锁）

解决「连接能不能建立」。同一台 VPS 上跑两个入站，端口互不冲突：REALITY 走 TCP/443，Hysteria2 走 UDP。

失效时的动作：换端口、换 dest、换 short_id：零成本、5 分钟。

出口层（纯净度）

解决「目标网站信不信任你」。E1 是 VPS 原生 IP（带宽最大），E2 是专门给 AI 的固定干净落地。

两条入口共用同一个本机 IP，这正是 AI 必须绕开 E1 的原因。

分流层（体验）

解决「谁走哪条路」。先 sniff 拿域名，再按 rule_set 决策：国内直连、AI 走 E2、其余走 E1。

失效时的动作：更新远程规则集、改 final。

05协议与入口：主备组合

两个协议解决的问题不同，组合使用比押注单一协议更符合「稳定性优先」。两个入站同时跑在同一台 VPS 上，切换只发生在客户端。

主入口 · VLESS + XTLS-Vision + REALITY（TCP/443）

  • 握手伪装成访问真实存在的第三方站点（如 www.apple.com），对 DPI 与主动探测的隐匿性仍是第一梯队
  • 不需要域名、不需要证书，因此没有「证书过期」这个失效源
  • 走 TCP/443，与正常 HTTPS 同端口，不受 UDP 限速策略影响
  • 约束：handshake.server 必须与 server_name 一致，且与 VPS 同区域、支持 TLS1.3 + HTTP/2；short_id 随机非空；两端时间同步（max_time_difference 默认 60s）

备入口 · Hysteria2（QUIC/UDP）

  • Brutal 拥塞控制不把丢包当拥塞信号，弱网/抖动链路上更容易维持吞吐
  • 2026 年必须叠加三件事：obfs salamander（对抗 QUIC 特征识别）、端口跳跃（对抗单端口 QoS）、客户端设置 up/down_mbps（触发 Brutal，不设则退化为普通 BBR）
  • 代价：完全依赖 UDP。校园网/公司网/部分运营商可能直接限制 UDP

谁做主入口：用实测决定，不要照抄

06一次 ChatGPT 请求如何被分流

这张时序图解释了「AI 出口解耦」到底解耦了什么：AI 域名在客户端就被挑出来，走独立落地节点，不经过主出口。

规则顺序不能错

1 sniff 拿域名 → 2 接管 DNS → 3 私有地址直连 → 4 AI 域名走 E2 → 5 广告拒绝 → 6 geosite-cn/geoip-cn 直连 → 7 其余走 E1。

不 sniff 就没有域名，规则只能按 IP 判断，CDN 与国内站点会误判。

DNS 必须防泄露

国内域名用国内 DoH（走直连出站）；境外域名用远端 DoH（走代理出站）；禁止明文 53 直连境外。

strategy: ipv4_only 减少一次 AAAA 往返、降低首字节延迟。

规则 / 全局双配置

sing-box 不区分「模式」，差别只是规则集与 final 的组合：全局模式即删掉国内直连那一条。

维护两份配置比在 GUI 里来回点更可复现。

07IP 纯净度与 AI 出口

分数只是门票，实测解锁才是准绳。出口分三级：E1 主出口、E2 AI 出口、E3 兜底。

Fraud Score 的口径必须说清 官方社区

官方阈值 vs 本方案门槛

IPQS 的 Fraud Score 是 0–100，越高越脏。官方口径是「≥85 高度可疑、≥90 建议直接拦截」；「0–20 干净」属于偏严格的社区口径。

本方案采用 ≤20 作为自建机的硬门槛，这是主动加严，不是官方标准。

低分不等于 AI 可用

IDC 机房的 IP 即使分数低，也可能因 IP 段属性触发挑战。「原生 IP」也不等于「住宅 IP」，两者都要看。

所以门禁必须包含实测解锁这一步。

门禁流程：下单后 5 分钟跑完，不过关就不部署

第 1 步IPQS：fraud_score、proxy、vpn、tor、recent_abuse、ASN
第 2 步ASN 与 IP 类型（ipinfo.io / ip.ping0.cc）：是否原生、是否宿主段
第 3 步实测解锁：ChatGPT 登录对话、Gemini、Claude、Google 是否弹验证码
第 4 步不合格直接换 IP 或换机：禁止先部署再发现
步骤看什么通过标准
1IPQS 免费检测：fraud_score、proxy、vpn、tor、recent_abuse、bot_status、ASNscore ≤20，且 proxy / vpn / tor / recent_abuse 均为 false
2ASN 与 IP 类型ASN 明确；区分「原生 IP」与「住宅 IP」
3实测解锁（浏览器）无 1020、无无限 challenge、可正常对话
4不合格时立即换 IP / 换机，不进入部署阶段

为什么 WARP 只能兜底 社区

观察结果来源
OpenAI 对 SNI(chatgpt.com) + 源 IP(WARP IPv4) 做定向 TLS 拒绝（例：104.28.x.x）ChatGPT 直接 4xx/5xx，换回 VPS 原生 IP 即恢复社区实测 2026-08
WARP 出口取就近 Cloudflare 接入点，地区会漂移账号地区漂移 → 风控 / challengeCloudflare 社区报告

与原稿的关键修正：原稿建议「AI 流量优先走 WARP」。按上面的实测，改为 E2 固定干净落地为第一优先，WARP 只在 E2 不可用时临时顶上，并接受它随时可能被拒。

出口纪律（比换出口更省事）

  • AI 出口的国家/地区不要频繁变化，浏览器、终端、API 尽量共用同一出口
  • AI 出口不跑 BT / 大流量下载，不与多人共用账号
  • 固定用 v4 出站（strategy: ipv4_only），避免「计划走 v4、实际走 v6」
  • 每周复测 IPQS + 解锁，记录趋势（分数上升通常是同段 IP 被人滥用）

08故障分级与降级切换

「稳定」不是不出故障，而是故障可定位、动作有顺序、成本从低到高。降级顺序：换入口参数 → 换 AI 出口 → 迁移或换机。

稳定性兜底清单

传输层

  • net.core.default_qdisc=fq + tcp_congestion_control=bbr
  • 提高 rmem_max / wmem_max（QUIC 大带宽受益）
  • 开启 tcp_fastopen

系统与证书

  • SSH 仅密钥、改端口、fail2ban、ufw 只放行必需端口
  • Hysteria2 证书用 acme.sh DNS-01 自动续期 + 到期告警
  • NTP 时间同步：REALITY 握手依赖时间窗

观测与备份

  • 客户端用 Clash API 面板看「走了哪个出站」
  • 服务端只看资源与流量，不记录客户端 IP / 访问域名
  • 配置入私有 Git，变更前备份 + sing-box check
