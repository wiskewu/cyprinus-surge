2 · 安装与密钥

目标：装好固定版本的 sing-box，生成本节点的参数与设备名单。执行者是有服务器 root 权限的人；做完后 /etc/sing-box 下应出现三个文件。

前提

  • 已跑完第 1 步：密码登录已关，公钥能登录
  • 服务器能访问 github.com 下载 sing-box；不能访问就先把二进制传到服务器，见下文「离线安装」
  • 两条命令都需要 root

执行

cd /root/deploy
sudo bash bin/deploy/one/install-singbox.sh
sudo bash bin/deploy/one/secrets.sh

bin/deploy/one/secrets.sh 逐项提问，回车取方括号里的默认值：

提问默认怎么填
伪装站点 REALITY_DESTwww.apple.com必须支持 TLS 1.3 与 HTTP/2。它同时是 REALITY 的回源目标，选错会让客户端握手失败
入口域名 DOMAIN留空只有要用 Hysteria2 才填。留空时客户端连公网 IP，证书流程整段跳过
启用 Hysteria2？Y仅在填了域名时出现。选 n 就只开 REALITY 单入口
第一台设备的名字main写进 devices.list。只允许字母、数字与 . _ -

成功的样子

[+] 已安装：sing-box version 1.14.3
[+] 已生成：/etc/sing-box/deploy.env / /etc/sing-box/client.env / /etc/sing-box/devices.list
[+] 完成：22 4061 / 443/tcp / 8443-8447/udp 已放行

完成：1 个步骤成功，0 个失败

版本号随 SING_BOX_VERSION 变。核对文件：

ls -l /etc/sing-box

应看到 deploy.env、client.env、devices.list 三个文件。权限随后续步骤变化，属正常：

阶段目录文件原因
刚生成密钥700 root:root600只有 root 需要读
降权后750 root:sing-boxconfig.json 组内可读进程以 sing-box 身份跑，要能读到配置

用 stat -c '%a %U:%G %n' /etc/sing-box /etc/sing-box/*.env 核对，比记住数字可靠。

产物

文件内容去向
/etc/sing-box/deploy.env服务端参数，含 REALITY 私钥只留服务器，不进仓库、不进备份的明文包
/etc/sing-box/client.env渲染客户端配置要用的参数第 5 步在客户端机器上用
/etc/sing-box/devices.list设备名、凭据、平台，一台一行只留服务器。加设备用 bin/deploy/device.sh，见第 3 页

换版本与离线安装

sudo SING_BOX_VERSION=1.15.0 bash bin/deploy/one/install-singbox.sh
sudo SING_BOX_PKG=/root/sing-box.tar.gz bash bin/deploy/one/install-singbox.sh
重装只换二进制，不动已加固的单元。install-singbox.sh 发现单元以 sing-box 运行时原样保留，/var/lib/sing-box 与 /etc/sing-box 的属主按单元的实际运行用户重新归位。要退回 root 全权限运行用 bin/harden/harden.sh --revert。
单元与运行目录属主必须一致。旧版本脚本会把单元改回 User=root 而 /var/lib/sing-box 仍属 sing-box：root 的能力集里没有 CAP_DAC_OVERRIDE，750 目录的 o 位没有 x，重启表现为 chdir /var/lib/sing-box: permission denied。现在 install / system / server 三步都调用 ensure_run_dir，按单元的实际用户递归归位，cache.db 这类上一次运行留下的文件也在内。

重跑与换密钥

bin/deploy/one/secrets.sh 在 deploy.env 已存在时直接保留原样并退出；deploy.sh 里的 secrets 步骤即使选「覆盖」也保留三样东西：

  • devices.list：设备凭据不因重跑而全变一遍；
  • REALITY 密钥对与 short_id：公钥嵌在已导出的客户端配置里，换了所有客户端当场失效；
  • OBFS_PASSWORD：Hysteria2 的 salamander 密码同理，换了表现为 QUIC 握手失败。
# 重跑：只补缺的字段，客户端配置继续有效
sudo bash bin/deploy/one/secrets.sh
sudo bash deploy.sh --only secrets --overwrite --yes

# 真的要换 REALITY 密钥（会作废所有已导出的客户端配置）
sudo FORCE_ROTATE_REALITY=1 bash deploy.sh --only secrets --overwrite --yes
sudo bash bin/deploy/device.sh export 每台设备名      # 逐台重新导出并分发
FORCE_ROTATE_REALITY=1 之后，没重新导出的客户端全部连不上。现象是客户端 REALITY 校验失败，服务端日志为 REALITY: processed invalid connection。只想换单台设备的凭据用 device.sh rotate，不动 REALITY 密钥。
