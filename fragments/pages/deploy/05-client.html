5 · 客户端

在客户端机器上拿到属于自己的那份配置，用 sing-box 命令行或平台客户端跑起来，并完成验收。凭据由服务器按设备发放，一台一份；客户端不需要 client.env、不需要密钥包，也不需要仓库里的脚本。

目标

完成后应达到三个状态：配置来自服务器按设备渲染的产物；本机以 TUN 方式接管流量，或至少有可用的本地代理端口；bin/deploy/client/verify.sh 逐项通过。

准备工作

拿到本机的那一份包

服务器为每台设备渲染一份 JSON，并按设备打包，包内附 SHA256SUMS。客户端只接收、校验、运行，不参与渲染。

平台取值产物入站适合
desktop-desktop.jsontun + mixed:2080Windows / macOS / Linux，命令行可直接验收
android-android.jsontunsing-box 官方 App
ios-ios.jsontunSFM 等 iOS 客户端

平台在服务器执行 device.sh add 时确定。同一台机器要用两个平台，按两个名字建两条凭据，各自可单独吊销。

Windows 的额外准备

  • sing-box 官方 Windows 包，解压到固定目录，例如 C:\sing-box
  • wintun.dll 与 sing-box.exe 放在同一目录，TUN 入站需要它在运行时加载
  • 以管理员身份运行，TUN 创建虚拟网卡需要提权
  • 工作目录设为配置所在目录，配置里的 cache.db 是相对路径

实施步骤

服务器：建凭据并打包

# 名单里没有这台时先建凭据
sudo bash bin/deploy/device.sh add laptop

# 渲染该设备配置并打包，产物在 /etc/sing-box/clients/dist/
sudo bash bin/deploy/device.sh export laptop

export 会打印可直接复制的分发命令，包含端口、用户与地址。

客户端：校验与解包

scp -P 你的SSH端口 root@服务器IP:/etc/sing-box/clients/dist/laptop-*.tar.gz* /tmp/
cd /tmp && sha256sum -c laptop-*.tar.gz.sha256 && tar -xzf laptop-*.tar.gz

在 ~/.ssh/config 里配好 Host 别名后，第一行可简写为 scp vps:/etc/sing-box/clients/dist/laptop-*.tar.gz* /tmp/。macOS 没有 sha256sum，用 shasum -a 256 -c laptop-*.tar.gz.sha256。

解出的文件名形如 sing-box-client-laptop-desktop.json，中间是设备名，末尾是平台。包里只有这一台设备的配置与校验和。

Windows：命令行运行

把配置放到 C:\sing-box\config.json，在管理员 PowerShell 里前台运行：

cd C:\sing-box
.\sing-box.exe check -c config.json      # 先校验，不通过不要启动
.\sing-box.exe run -c config.json

前台运行便于观察日志。确认可用之后再交给任务计划常驻：

$dir = "C:\sing-box"
$act = New-ScheduledTaskAction -Execute "$dir\sing-box.exe" -Argument "run -c $dir\config.json" -WorkingDirectory $dir
$trg = New-ScheduledTaskTrigger -AtStartup
$trg.Delay = "PT20S"
$set = New-ScheduledTaskSettingsSet -AllowStartIfOnBatteries -DontStopIfGoingOnBatteries `
       -RestartCount 3 -RestartInterval (New-TimeSpan -Minutes 1) `
       -ExecutionTimeLimit ([TimeSpan]::Zero)
$prn = New-ScheduledTaskPrincipal -UserId "SYSTEM" -RunLevel Highest
Register-ScheduledTask -TaskName "sing-box" -Action $act -Trigger $trg -Settings $set -Principal $prn

三个参数不能省：-WorkingDirectory 决定 cache.db 落点，Delay 等网络就绪，ExecutionTimeLimit 默认 3 天会把任务停掉。需要日志与崩溃重启时，改用 nssm 或 WinSW 包装成服务：

nssm install sing-box C:\sing-box\sing-box.exe
nssm set sing-box AppParameters run -c C:\sing-box\config.json
nssm set sing-box AppDirectory  C:\sing-box
nssm set sing-box Start SERVICE_AUTO_START
nssm set sing-box AppExit Default Restart
nssm set sing-box AppStdout C:\sing-box\logs\stdout.log
nssm set sing-box AppStderr C:\sing-box\logs\stderr.log
nssm start sing-box

管控机：两种改法

受管终端禁止直连公共 DNS 的 443 与 853 时，配置里的国内 DoH 会让启动失败，报 connectex: The requested address is not valid in its context。用 bin/win/convert.sh 就地生成两种可用版本，不改动服务器下发的那份：

# 方式一：给 direct 出站指定源地址，源地址默认取默认路由网卡的 IPv4
bash bin/win/convert.sh 客户端配置.json --mode bind

# 方式二：国内解析交给系统
bash bin/win/convert.sh 客户端配置.json --mode local

# 指定源地址或输出路径
bash bin/win/convert.sh 客户端配置.json --mode bind --bind-address 192.168.8.150 --out .\config.json

产物默认落在源文件旁边，文件名带 -bind 或 -local 后缀。脚本会依次在配置目录、当前目录与 PATH 里找 sing-box 并校验产物；找不到就跳过，用 --sing-box 指定。两种改法的原因与判据见排查手册。

macOS：只留一个客户端

两台代理客户端同时接管流量时，症状无法归因：断流、DNS 泄漏、TUN 抢路由三者互相掩盖。统一用 SFM，其余客户端全部退出并停用系统代理。

# 1. 关掉其他客户端的接管，退出 App（含菜单栏图标）
#    Clash Verge：设置里关「系统代理」，关「TUN 模式」，再退出

# 2. 确认系统代理已清空，三项都应为 Enabled: No 或不存在
scutil --proxy | grep -Ei 'HTTPProxy|HTTPSProxy|SOCKSProxy|ProxyAutoConfig'
networksetup -getwebproxy Wi-Fi
networksetup -getsecurewebproxy Wi-Fi
networksetup -getsocksfirewallproxy Wi-Fi

# 3. 确认没有残留的 utun 接口与默认路由
ifconfig | grep '^utun'
route -n get default | grep -E 'interface|gateway'

# 4. 只留 SFM：首次启动按提示授权系统扩展，再导入 JSON，最后打开 TUN

# 5. 确认默认路由进了 SFM 的 utun，且能出网
route -n get default | grep interface
curl -s -o /dev/null -w '%{http_code}\n' https://www.gstatic.com/generate_204
桌面客户端导入的是副本。服务器重新导出后必须重新导入，直接改手里那份 JSON 对已经运行的配置无效。SFM 的副本在 ~/Library/Group Containers/P8XK3KHB48.io.nekohasekai.sfamt/configs/。

Android 与 iOS：导入

Android 用 sing-box 官方 App 导入 -android.json，iOS 用 SFM 导入 -ios.json，两者只有 TUN 入站。手机上没有 sha256sum，校验可在电脑上完成后再传。

检查与验证

桌面配置自带本地端口 127.0.0.1:2080，验收脚本默认就用它；客户端换端口时显式传 --proxy。

SERVER_IP=你的服务器IP bash bin/deploy/client/verify.sh --no-cli --proxy socks5h://127.0.0.1:2080
检查项免 CLI 子集完整验收
代理可用与境外出口有有
分流：国内站点是否直连有有
AI 站点可达性有有
出口是否稳定有有
延迟分解跳过，需要读配置有
握手质量跳过，需要 SERVER_IP 与 mtr有

免 CLI 子集是子集而非完整验收：跳过项与 SERVER_IP 缺失都会明确打印，不会被当成通过。整机都走隧道时「国内直连」一项会判失败，那是环境决定的，不代表配置有问题。各项输出含义见排查手册。

两个配置层面的判据也在这里核对：

  • 规则集缓存已落盘。运行目录下应出现 cache.db，重启不再整份重下。
  • 服务器 IP 直连生效。TUN 运行时 ssh 到服务器不应被断；断开说明 route.rules 第一条缺失，重新导出该设备配置。

回退与卸载

场景服务器客户端
凭据泄露或定期轮换bin/deploy/device.sh rotate laptop，再 export重新导入新包，旧包立即失效
设备退役bin/deploy/device.sh revoke laptop删除机器上的 JSON 与已导入的副本
新配置跑不起来不动重新导入手里上一版的包；旧包只在凭据未轮换时可用
Stop 客户端不动Windows 前台运行按 Ctrl+C；任务计划用 Stop-ScheduledTask -TaskName sing-box；服务用 nssm stop sing-box

命令手册

# 服务器：建立凭据并导出
sudo bash bin/deploy/device.sh add laptop [desktop|android|ios]
sudo bash bin/deploy/device.sh export laptop

# 客户端：校验、解包、运行
sha256sum -c laptop-*.tar.gz.sha256 && tar -xzf laptop-*.tar.gz
cd C:sing-box && .sing-box.exe check -c config.json
.sing-box.exe run -c config.json

# 管控机：生成可用版本并启动
bash bin/win/convert.sh 客户端配置.json --mode bind      # 或 --mode local
bash bin/win/run.sh 客户端配置-bind.json                  # 先校验再前台运行

# 客户端：验收
SERVER_IP=你的服务器IP bash bin/deploy/client/verify.sh --no-cli --proxy socks5h://127.0.0.1:2080

参数说明

项取值说明
verify.sh --no-cli开关只用本地端口，不起 sing-box 实例
verify.sh --proxysocks5h://127.0.0.1:端口客户端实际监听端口，默认 2080
SERVER_IP服务器 IP用于比对出口与握手质量，服务器上 grep SERVER_IP /etc/sing-box/client.env 可取
VLESS_PORT默认 443REALITY 入口端口
HY2_ONLY=1开关派生只走 Hysteria2 的配置并起临时实例，需要本机有 sing-box
CONFIG路径HY2_ONLY 读取的配置，指向设备 JSON
experimental.cache_file.pathcache.db相对运行目录；要固定位置在服务器渲染前给 SING_BOX_CACHE_FILE
缓存写法有版本要求。1.13 起顶层 cache_file 被移除，必须写在 experimental.cache_file 里且为对象形式 {"enabled": true, "path": "..."}，写成字符串会被拒绝启动。服务器模板已按新写法生成。

常见错误与排查

现象原因处理
启动即报 connectex: The requested address is not valid in its context企业终端策略禁止直连公共 DNS 的 443 与 853见排查手册的企业管控一节
ssh 到服务器立刻被断服务器 IP 未直连，流量被 TUN 绕回本机重新导出该设备配置，不要手改 JSON；或在渲染时确认 SERVER_IP 已写入
国内站点很慢或走境外规则集未加载，全部走代理确认运行目录下 cache.db 已生成，再看连接列表的 chains
端口不一致，验收第一项就失败客户端自己改了监听端口验收时传 --proxy socks5h://127.0.0.1:实际端口
日志出现 not valid in its context 且非企业管控多网卡或虚拟网卡的 Windows 上接口绑定失败让服务器重渲染该设备时带 AUTO_DETECT_INTERFACE=false DEFAULT_INTERFACE=网卡名，再导出
缓存文件出现在 System32启动时的工作目录不是配置目录任务计划补 -WorkingDirectory，nssm 补 AppDirectory
