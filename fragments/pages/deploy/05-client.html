5 · 客户端

目标：在客户端机器上拿到一份可导入的配置，并让它以 TUN 或本地端口工作。读者是自己设备的用户；需要的东西只有服务器发来的那一份 JSON。

取参数并渲染

# 你的电脑上
scp root@你的服务器IP:/etc/sing-box/client.env ./client.env

一条命令复位客户端

bash bin/deploy/client/install.sh --keys client.env --device main   --ssh-host 203.0.113.10 --ssh-port 4061
步骤做什么跳过
1 SSH 免密沿用 bin/harden/client.sh：生成或复用 Ed25519、装公钥、写 ~/.ssh/config--skip-ssh 或不给 --ssh-host
2 渲染配置调用 bin/deploy/client/render.sh，产物在 data/不可跳过
3 验收调用 bin/deploy/client/verify.sh，图形客户端加 --no-cli--skip-verify

不需要 root。依赖只有 curl 与 jq，缺 jq 直接停并给出安装命令；--check 只报告本机依赖与文件状态。

验收失败不等于配置不可用。脚本会停止但不删除已渲染的配置，因为多数失败来自代理没启动或端口不对；按提示先导入客户端再复测。

规则集缓存

分流依赖三个远程规则集。渲染时写入 experimental.cache_file，下载结果与编译结果落盘，重启不再整份重下；规则集自身的 update_interval 是 3 天，到期由 sing-box 自行刷新。

项服务端客户端
缓存路径/var/lib/sing-box/cache.db~/.cache/sing-box/cache.db
覆盖方式SING_BOX_CACHE_FILESING_BOX_CACHE_FILE
刷新周期规则集 update_interval 3 天同左
写法有版本要求。1.13 起顶层 cache_file 被移除，必须写在 experimental.cache_file 里且为对象形式 {"enabled": true, "path": "..."}；写成字符串会被 sing-box 拒绝启动。

没有 CLI 时怎么验收

图形客户端把核心装在扩展或 App 里，本机没有 sing-box 可执行文件。这时用免 CLI 子集：

bash bin/deploy/client/verify.sh --no-cli --proxy socks5h://127.0.0.1:7890
检查项免 CLI 子集完整验收
代理可用与境外出口有有
分流：国内站点是否直连有有
AI 站点可达性有有
出口是否稳定有有
延迟分解跳过，需要读配置有
握手质量跳过，需要 SERVER_IP 与 mtr有
这是子集，不是完整验收。跳过项与 SERVER_IP 缺失都会明确打印，不会被当成通过。反向代理整机都走隧道时，「国内直连」一项会判失败，那是环境决定的结果，不代表客户端有问题。
多台设备用 bin/deploy/device.sh，不要用本页的方式。本页的 client.env 里只有一台设备的凭据（bin/deploy/one/secrets.sh 写的 main），多台共用同一个 uuid 就没法单独吊销。服务端跑 sudo bash bin/deploy/device.sh add laptop 会直接生成那台的配置，你只管 scp 过去。见 第 3 页。验收那一步同样不需要 client.env：SERVER_IP=... bash bin/deploy/client/verify.sh（见 第 6 页）。

一次生成三端

bash bin/deploy/client/render.sh ./client.env --all   # 默认输出到 ./data
产出（在 data/）入站预设覆盖
sing-box-client-desktop.jsontun + mixed:2080无（沿用 client.env）
sing-box-client-android.jsontunCLIENT_MIXED=0、auto_detect_interface=true
sing-box-client-ios.jsontun同上

多端模式只覆盖这两项「平台相关」的值，其余（节点、DNS、AI 出口、规则）都来自 client.env，所以三份配置的规则完全一致。

规则第一条是「服务器自己的 IP 直连」。这是必须的：开着 TUN 时，连服务器的流量（包括 SSH、SPA 敲门包）也会被送进隧道，从隧道出口又绕回这台 VPS（hairpin），表现为「nc 能通但 ssh 立刻被关」。脚本会读 client.env 里的 SERVER_IP 自动生成这条规则；拿不到 IP 就只警告不写。
桌面报 not valid in its context（多网卡 / 虚拟网卡的 Windows 常见）：用两个变量一起关掉自动探测、并显式指定物理网卡：
AUTO_DETECT_INTERFACE=false DEFAULT_INTERFACE=en0 bash bin/deploy/client/render.sh ./client.env desktop
只关不绑 = 直连会打环：auto_detect_interface=false 之后出站不再绑物理网卡，direct 出站会按默认路由又走回 tun，表现为“能连上、立刻被断”。脚本会渲染成 route.default_interface，并在你忘了给网卡名时把本机物理网卡打印出来提醒。默认值是 true，TUN 下它顺手把环也挡掉了。
GUI 客户端（SFM / Clash Verge / GUI.for.SingBox）导入的是副本。重新渲染后必须重新导入，或者手动把新 JSON 贴进去，直接改仓库里那份或改 data/ 下的文件对已经导入的配置无效。SFM 的导入副本在 ~/Library/Group Containers/P8XK3KHB48.io.nekohasekai.sfamt/configs/。

只生成某一份 / 完全自定义

# 只生成安卓
bash bin/deploy/client/render.sh ./client.env android

# 单份模式：完全按 client.env 与命令行变量
OUT=./me.json bash bin/deploy/client/render.sh ./client.env

# 换输出目录
OUTDIR=/tmp/x bash bin/deploy/client/render.sh ./client.env --all

产物一律落在 OUTDIR（默认 ./data，已在 .gitignore 里），不会往脚本目录写。改完 client.env 后重跑即可覆盖同名文件。
