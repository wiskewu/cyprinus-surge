6 · 验收与备份

目标：确认节点真的可用，并留下能恢复的备份。验收命令在客户端机器执行，备份与日常检查在服务器执行。

验收（客户端机器）

bash bin/deploy/client/verify.sh ./client.env

退出码：0 全过 / 1 有失败项 / 2 本地代理没起来（后面的检查已跳过）。
用 GUI.for.SingBox 时端口不同，要显式指定：PROXY=socks5h://127.0.0.1:GUI端口 bash ...

用 bin/deploy/device.sh 管设备时：不传 client.env

走 第 3 页的设备流程时，客户端拿到的只有服务器发过去的那份 JSON。client.env 不要发过去：里面是 main 的凭据加密钥包，与“一台设备一份凭据”相背。 验收脚本真正读的只有 SERVER_IP 与 VLESS_PORT，直接给变量就行：

SERVER_IP=你的服务器IP VLESS_PORT=443 bash bin/deploy/client/verify.sh

# 用 GUI.for.SingBox 且端口不同时，两个变量一起给
SERVER_IP=你的服务器IP PROXY=socks5h://127.0.0.1:20122 bash bin/deploy/client/verify.sh

# 只验 Hysteria2 出站：脚本自己派生配置、起临时实例、跑完清理（需要本机有 sing-box）
HY2_ONLY=1 CONFIG=./client.json SERVER_IP=你的服务器IP VLESS_PORT=443 \
  bash bin/deploy/client/verify.sh

# 没有 sing-box CLI：只生成一份只走 hy2 的配置，导入图形客户端后再验收
HY2_ONLY=emit CONFIG=./client.json HY2_OUT=./hy2-only.json \
  bash bin/deploy/client/verify.sh
# 导入后：PROXY=socks5h://127.0.0.1:<客户端端口> SERVER_IP=你的服务器IP \
#   bash bin/deploy/client/verify.sh

没 env 文件时脚本会打一行提示后继续（VLESS_PORT 默认 443）；SERVER_IP 也不给才会报错退出。SERVER_IP 不是凭据，全设备通用，回服务器看一眼就知道：

grep SERVER_IP /etc/sing-box/client.env     # 只是取 IP，不是拷走凭据
sudo bash bin/deploy/device.sh list                   # 确认这台在名单里
手机那份配置跑不了这个脚本。-android.json / -ios.json 只有 TUN，没有本地 2080 端口，第一项就 exit 2。手机只能在 App 里直接开浏览器自查（国内站点、Google、ChatGPT 各开一个）；要用回环脚本就把桌面那份导进来测。

备份（服务器）

cd /root/deploy
bash bin/deploy/ops/backup.sh backup     # 备份到 /root/backups/
bash bin/deploy/ops/backup.sh list
bash bin/deploy/ops/backup.sh restore /root/backups/sing-box-日期.tgz

备份含私钥，等同机器凭据，别放网盘或仓库。/etc/sing-box 整个目录都会进包，所以 devices.list 与 clients/*.json 也在里面，一份备份等于全部设备的凭据，泄露就得挨个 device.sh rotate。

日常三条

vnstat -m                              # 本月流量（套餐 1TB/月，超了限速 1Mbps）

观测：clash_api 与定时探针 可选

节点出问题时的两类问题（「服务还在不在」与「出口有没有被风控」）靠猜不准，用 bin/deploy/ops/monitor.sh 记成时序。

sudo bash bin/deploy/ops/monitor.sh              # 一键：打开 clash_api + 装 5 分钟探针 + 立刻跑一次
sudo bash bin/deploy/ops/monitor.sh --probe      # 只跑一次探针
sudo bash bin/deploy/ops/monitor.sh --status     # 看最近 20 条记录与 clash_api 概览
sudo bash bin/deploy/ops/monitor.sh --clash-api on|off
sudo bash bin/deploy/ops/monitor.sh --uninstall

探针记了什么

字段含义怎么用
tsUTC 时间戳对齐服务商故障与晚高峰
service / tcp / udpsing-box 状态、VLESS_PORT 是否监听、启用 Hy2 时 HY2_PORT/udp 是否监听先排除「进程挂了」
egress服务器直连 api.ipify.org 拿到的公网 IPIP 变了说明迁移或云厂商调度，客户端要重发配置
ai_code / ai_locchatgpt.com/cdn-cgi/trace 的状态码与出口地区出现 403 就是出口被风控，该换 AI 出口
loss_pct / rtt_avg_ms到 1.1.1.1 的丢包率与平均 RTT丢包长期 >2% 时，Hy2 的体验会明显劣于 REALITY

记录落在 /var/lib/sing-box-monitor/probe.log，只保留最近 5000 行。定时器是 sing-box-probe.timer，每 5 分钟一次。

clash_api 面板

开关由 deploy.env 的 ENABLE_CLASH_API 控制，开启后重渲染配置并写进 experimental.clash_api，只绑 127.0.0.1:9090。远程看要开 SSH 隧道：

ssh -N -L 9090:127.0.0.1:9090 root@你的服务器IP
# 浏览器打开 http://127.0.0.1:9090/ui
/ui 需要面板文件。clash_api 只提供 REST 接口，不自带前端，没装面板时访问 /ui 是 404。装一次即可：sudo bash bin/deploy/ops/monitor.sh --ui，它下载 metacubexd 到 /var/lib/sing-box/ui 并重渲染配置写入 external_ui。面板文件放在运行目录而不是 /etc/sing-box，避免被 bin/deploy/ops/backup.sh 打进每次备份。
不要把它绑到 0.0.0.0。面板能看到全部连接与规则命中，暴露公网等于把控制面交出去；本脚本固定写回环地址。
要按出口看连接数：curl -s http://127.0.0.1:9090/connections | jq '[.connections[].chains[-1]] | group_by(.) | map({(.[0]): length}) | add'。--status 已经做了这一步，没装 jq 时退回原始输出。

导出与回滚

分发一次不只发一个 JSON：包里带上校验和，收端先校验再导入，避免传输截断。

# 服务器：渲染 + 打包 + 出校验和，产物在 /etc/sing-box/clients/dist/
sudo bash bin/deploy/device.sh export laptop

# 客户端：先校验再解包
scp vps:/etc/sing-box/clients/dist/laptop-*.tar.gz* /tmp/
cd /tmp && sha256sum -c laptop-*.tar.gz.sha256 && tar -xzf laptop-*.tar.gz

包内只有这一台设备的配置和 SHA256SUMS，不含其他设备的凭据，也不含 client.env。

客户端每次重新渲染前会把现有配置存进 data/previous/<时间戳>/，只保留最近三版。新配置跑不起来时一条命令退回上一版：

bash bin/deploy/client/install.sh --rollback
回滚只替换 data/ 下的配置文件，不碰 SSH 免密，也不重跑验收。

备份与加密

备份默认加密：优先 gpg --symmetric，没有 gpg 时退回 openssl enc。两者都缺失时脚本拒绝生成明文包。

sudo bash bin/deploy/ops/backup.sh key      # 首次：生成备份口令，打印一次
sudo bash bin/deploy/ops/backup.sh backup   # 加密备份
sudo bash bin/deploy/ops/backup.sh list     # 列出，标注明文还是加密
sudo bash bin/deploy/ops/backup.sh restore /root/backups/sing-box-xxx.tgz.gpg
sudo bash bin/deploy/ops/backup.sh backup --insecure   # 明确要明文时才用
项值说明
口令文件/root/.backup-passphrase权限 600，可用 BACKUP_PASSPHRASE_FILE 改
产物sing-box-<时间>.tgz.gpg 或 .enc扩展名区分加密方式，恢复时自动识别
备份范围/etc/sing-box 与 systemd 单元面板文件在运行目录，不进备份
口令与备份必须分开存放。口令丢失时加密包无法恢复：它们互为唯一打开条件，放在同一处等于没加密。

凭据轮换

轮换会立刻让旧客户端配置失效，脚本在动作前要求确认，非交互环境必须显式给 --yes。

sudo bash bin/deploy/rotate.sh short-id        # 换 REALITY short_id
sudo bash bin/deploy/rotate.sh obfs            # 换 Hysteria2 obfs 密码，需 ENABLE_HY2=1
sudo bash bin/deploy/rotate.sh device main     # 换单台设备
sudo bash bin/deploy/rotate.sh devices         # 换全部设备
sudo bash bin/deploy/rotate.sh all             # 三项依次执行
sudo bash bin/deploy/rotate.sh all --dry-run   # 只打印计划

每次轮换都会重渲染服务端配置并重启 sing-box。收尾三步由脚本打印：重渲染客户端、让对方删除旧配置后重新导入、清理旧凭据所在的备份与聊天记录。

轮换不是吊销。只把凭据换掉，旧设备上的配置仍能读到旧凭据；确认作废要同时删除对应设备行或用 bin/deploy/device.sh revoke。
