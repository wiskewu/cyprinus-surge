一键脚本

deploy.sh 把七个步骤串起来：先扫描每一步是否已配置，再让你决定「复用 / 覆盖 / 跳过」。它由 build-onekey.sh 生成，内容就是 lib.sh 加 steps/*.sh 加驱动逻辑。

目标

用一条命令完成或补齐部署，同时保留逐步执行的等价入口：每个步骤都能单独重跑，单步脚本与一键脚本调用同一份实现，行为一致。

准备工作

scp -r bin root@你的服务器IP:/root/
ssh root@你的服务器IP
cd /root/bin/deploy && bash deploy.sh

不带参数即交互模式。想先看它要做什么：bash deploy.sh --dry-run。涉及 Hysteria2 时需要先备齐域名、Cloudflare API Token 与邮箱，缺失会直接退出码 2。

交互模式

收尾输出

所有步骤成功时脚本最后打印下面几条，命令里的路径已换成本机实际位置：

下一步
  当前设备：mac
  新增设备：sudo bash /root/bin/deploy/device.sh add <名字> [desktop|android|ios]
  导出这一台的配置：sudo bash /root/bin/deploy/device.sh export <名字>
  换凭据：sudo bash /root/bin/deploy/device.sh rotate <名字>　　吊销：sudo bash /root/bin/deploy/device.sh revoke <名字>
  客户端导入后验收：bash bin/deploy/client/verify.sh

export 会把这一台的 JSON 打包成 /etc/sing-box/clients/dist/<名字>-<UTC时间>.tar.gz，并打出填好 SSH 端口、用户与服务器 IP 的 scp 命令。传输由客户端发起，源在服务器一侧、目标在本地当前目录：

[+] 已导出：/etc/sing-box/clients/dist/mac-20261026T123626Z.tar.gz（4.0K）
[+] 包内校验和：ed1509c7a459c75486e38c7fd1902a443947e57b7465fcde4d9851864876c671
[+] 分发（在客户端执行；源在服务器，目标在本地当前目录）：
[+]     scp -P 4061 root@203.0.113.9:/etc/sing-box/clients/dist/mac-20261026T123626Z.tar.gz \
          root@203.0.113.9:/etc/sing-box/clients/dist/mac-20261026T123626Z.tar.gz.sha256 .
[+] 校验并解包：sha256sum -c mac-20261026T123626Z.tar.gz.sha256 && tar -xzf mac-20261026T123626Z.tar.gz    # macOS 用 shasum -a 256 -c

端口与地址取自 deploy.env 的 SSH_PORT 与 SERVER_IP；登录用户默认 root，可用 SSH_LOGIN_USER 覆盖。

检查与验证

bash deploy.sh --status      # 只看每一步的状态，不做改动
bash deploy.sh --dry-run     # 打印计划与将执行的步骤

收尾还会检查已导出的客户端配置是否仍与服务器一致：比对 clients/*.json 里的 tls.reality.public_key、short_id 与 Hysteria2 混淆密码，与 deploy.env 不一致的设备会被点名并要求重新 export。这类配置连不上时客户端只报 reality verification failed。

下一步

服务器侧完成后，到第 5 页取该设备的配置并导入验收，再到第 6 页做备份与观测。

回退与卸载

bash deploy.sh --uninstall --yes     # 卸载，保留 deploy.env 与证书
bash deploy.sh --purge --yes         # 卸载并删除 deploy.env 与证书
bash deploy.sh --reinstall --yes     # 卸载后全量覆盖重装

--uninstall 会删除：sing-box 服务、二进制、systemd 单元与 /var/lib/sing-box；config.json、证书、Hysteria2 的 iptables 规则；本项目加的 ufw 规则（443、8443-8447）与 sysctl.d 优化文件。--purge 额外删除 deploy.env 与 client.env。

不会动的东西：SSH 端口的 ufw 规则、ufw 的启用状态、swap、/root/backups 里的备份。卸载后仍保持 SSH 可登录。

deploy.sh 是生成物，不要手改。改过 steps/*.sh 或 onekey/driver.sh 之后重新生成：

bash fragments/build/build-onekey.sh    # 生成 deploy.sh，并做 bash -n 语法检查

命令手册

# 只重做服务端配置（改完 REALITY_DEST 之类）
bash deploy.sh --only server --overwrite --yes

# 有域名后补开 Hysteria2
DOMAIN=vps.example.com CF_TOKEN=xxx ACME_EMAIL=me@example.com \
  bash deploy.sh --only hy2,server --overwrite --yes

# 定期轮换客户端可见密钥
bash deploy.sh --only secrets --rotate-secrets --yes
sudo bash bin/deploy/device.sh export 每台设备名

# 完全重装
bash deploy.sh --reinstall --yes

# 怀疑环境被污染：先卸载干净再来
bash deploy.sh --purge --yes && bash deploy.sh --yes

参数说明

参数作用
--reuse已配置的步骤一律复用，不提问
--overwrite已配置的步骤一律重跑并覆盖
--only a,b只跑指定步骤（system,install,secrets,hy2,server,harden,porthop）
--skip a,b跳过指定步骤
--yes不再确认，配合 --reuse 可全自动
--dry-run只打印计划和将执行的步骤
--status只看每一步的状态
--uninstall卸载，保留 deploy.env 与证书
--purge卸载并删除 deploy.env 与证书
--reinstall卸载后全量覆盖重装
--rotate-secrets重建密钥时换掉所有客户端可见的密钥：REALITY 密钥对、short_id、HY2 混淆密码。已导出的客户端配置立即失效

步骤与依赖

七个步骤名与部署手册的编号不是一一对应：脚本把「装 sing-box」和「生成密钥」拆成两步，Hysteria2 拆成发证与端口跳跃两步，并在服务端配置之后固定跑一次加固。

手册对应 deploy.sh 步骤在哪台机器
1 系统初始化system服务器
2 装 sing-box 与生成密钥install 到 secrets服务器
3 服务端配置与自检server 到 harden服务器
4 Hysteria2（可选）hy2（证书，排在 server 之前）到 porthop服务器
5 客户端配置不在本脚本内客户端机器
6 验收与备份不在本脚本内两边
步骤文件可选已配置的判定
systemsteps/10-system.sh否sysctl 存在、ufw 已启用、BBR 已开、密码登录已关
installsteps/20-install.sh否二进制与 systemd 单元都在
secretssteps/30-secrets.sh否deploy.env、client.env、devices.list 都存在
hy2steps/35-hy2.sh是证书存在且 ENABLE_HY2=1
serversteps/40-server.sh否config.json 存在且服务在运行
hardensteps/55-harden.sh否单元含 User=sing-box 与 NoNewPrivileges=yes，服务运行中
porthopsteps/60-porthop.sh是iptables 里已有重定向规则

表里的顺序就是执行顺序。两个可选步骤只在 ENABLE_HY2=1 时执行，否则自动跳过并说明原因。hy2 排在 server 之前，因为渲染服务端配置要读 cert.pem 与 key.pem，缺证书时 server 直接失败。harden 排在 server 之后、porthop 之前，因为沙箱化后要验证 Hy2 端口，证书与服务端配置都就位时 8443 才会监听。

常见错误与排查

现象原因处理
--yes 下直接退出码 2材料清单里有缺失项，脚本不进入执行按提示补齐环境变量，例如 DOMAIN、CF_TOKEN、ACME_EMAIL
重跑 secrets 后客户端全部失效选择了换新密钥逐台 device.sh export 重新分发；只想换单台设备用 device.sh rotate
hy2 被跳过ENABLE_HY2 不为 1在 secrets 里启用并重跑 --only secrets,hy2,server --overwrite --yes
system 一直显示未配置没有可用公钥时不把「密码登录已关」计入先按第 1 页装公钥，再重跑
手工改过 deploy.sh 后行为异常该文件是生成物，手改会在下次生成时被覆盖改 steps/*.sh 或 onekey/driver.sh，再跑 build-onekey.sh
