验收与排障

加固完成后独立确认结果：脚本在客户端运行，只读，不动任何一端。本页给出输出含义、失败项对照与失联前的自救顺序。

目标

用一次远程连接确认四件事：本机准备就绪、密钥能登录、密码被拒、服务端生效值与运行态防护符合预期。任一项失败时能定位到具体环节。

准备工作

  • 已完成客户端配置与服务端加固
  • 本机存在 Ed25519 私钥，~/.ssh/config 里有对应别名
  • 当前会话保持打开，用于失联时执行回滚

实施步骤

bash bin/harden/audit.sh --alias vps
bash bin/harden/audit.sh --host 203.0.113.10 --port 4061

全部检查合并为一次远程连接，因为 ufw limit 对同一来源有速率限制，多次连接会把验收自己限住。

== 1. 本机准备 ==
  ✓ 本机存在 Ed25519 私钥：256 SHA256:…
  ✓ /root/.ssh/config 有 Host vps
== 2. 密钥登录 ==
  ✓ 公钥登录成功
== 3. 密码登录应被拒 ==
  ✓ 服务端只提供公钥方式，密码被拒
== 4. 服务端 sshd 生效值 ==
  ✓ passwordauthentication = no
  ✓ kbdinteractiveauthentication = no
  ✓ permitrootlogin = without-password
  ✓ pubkeyauthentication = yes
  ✓ maxauthtries = 3
  · MaxStartups = 5:30:10，LoginGraceTime = 20，ClientAliveInterval = 300
== 5. 运行态防护 ==
  ✓ 存在 LIMIT 速率限制规则
  ✓ 同端口没有全局 ALLOW 规则覆盖
  ✓ fail2ban sshd jail 已启用
  ✓ 服务端可用公钥数：3

通过 13 项，失败 0 项

permitrootlogin 显示 without-password 是 prohibit-password 的别名，含义相同。通过项数随服务端 sshd 的关键字与公钥数量变化，示例是 13 项；只看失败项。

检查与验证

脚本退出码 0 且无失败项即通过。日常核对也可以手工执行这几条：

sshd -T | grep -iE '^(passwordauthentication|permitrootlogin|maxauthtries|maxstartups)'
ufw status numbered | grep 4061
fail2ban-client status sshd
lastb | head -20

lastb 列出失败登录，配合 fail2ban 的封禁记录可以交叉验证，确认没有持续的定向尝试。

下一步

需要调整默认值、评估可选双因子，或了解哪些加固项被明确放弃时，见参数与取舍。

回退与卸载

验收不通过且无法当场修复时按下节的自救顺序处理，最后一步都是回滚：

sudo bash bin/harden/harden.sh --uninstall    # 在仍可用的会话里执行

命令手册

bash bin/harden/audit.sh --alias 别名          # 用 ~/.ssh/config 里的别名验收
bash bin/harden/audit.sh --host 地址 --port 端口  # 直接指定目标
bash bin/harden/harden.sh --uninstall          # 回滚服务端加固

参数说明

参数默认说明
--aliasvps读取 ~/.ssh/config 中的该名字
--host 与 --port无不走配置文件时直接指定目标
退出码无0 全过，非 0 表示存在失败项

常见错误与排查

现象原因处理
第 2 项失败，公钥登录不通公钥未装、用户名或端口不符、密钥权限过宽先解决这一项，后面的检查都以它为前提；ssh -v 看实际尝试的身份
第 3 项失败，仍提示密码某个排序更靠前的 drop-in 设了 PasswordAuthentication yesgrep -r PasswordAuthentication /etc/ssh/sshd_config*，改掉靠前那一行后 systemctl reload ssh
第 4 项读不到 sshd -T登录用户不是 root，且没有免密 sudo用 root 密钥登录，或给该用户配置 NOPASSWD 的只读命令
第 5 项提示「全局 ALLOW 规则覆盖」同端口还有一条不限来源的 ufw allowufw --force delete allow <端口>/tcp，保留 LIMIT 那一条
连接超时，ssh 无响应短时间内新连接过多，触发 ufw limit等 30 秒重试，规则按来源限制 6 次/30 秒
与服务器完全失联密码已关闭且密钥不可用走云控制台 VNC，执行 sudo bash bin/harden/harden.sh --uninstall

锁死之前的自救顺序。第一，不要关闭当前已登录的会话，它不受新配置影响，可以继续修；第二，在另一个终端验证密钥登录 ssh -o BatchMode=yes 别名 true；第三，失败时在当前会话里执行回滚，恢复密码登录；第四，修好公钥问题后重新加固，并再次用另一个终端验证。

会话断开策略。ClientAliveInterval 300 配 ClientAliveCountMax 2，空闲约 10 分钟断开。批量操作请放进 tmux，否则会在中途掉线。
