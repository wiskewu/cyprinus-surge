验收与排障

主读者：加固完成后要独立确认结果的人。本页给出验收脚本的输出含义，以及每个失败项对应的处理顺序。

验收

bash bin/harden/audit.sh --alias vps
bash bin/harden/audit.sh --host 203.0.113.10 --port 4061

脚本在客户端运行，只读，不改动任何一端。全部检查合并为一次远程连接，因为 ufw limit 对同一来源有速率限制，多次连接会把验收自己限住。

== 1. 本机准备 ==
  ✓ 本机存在 Ed25519 私钥：256 SHA256:…
  ✓ /root/.ssh/config 有 Host vps
== 2. 密钥登录 ==
  ✓ 公钥登录成功
== 3. 密码登录应被拒 ==
  ✓ 服务端只提供公钥方式，密码被拒
== 4. 服务端 sshd 生效值 ==
  ✓ passwordauthentication = no
  ✓ kbdinteractiveauthentication = no
  ✓ permitrootlogin = without-password
  ✓ pubkeyauthentication = yes
  ✓ maxauthtries = 3
  · MaxStartups = 5:30:10，LoginGraceTime = 20，ClientAliveInterval = 300
== 5. 运行态防护 ==
  ✓ 存在 LIMIT 速率限制规则
  ✓ 同端口没有全局 ALLOW 规则覆盖
  ✓ fail2ban sshd jail 已启用
  ✓ 服务端可用公钥数：3

通过 13 项，失败 0 项

permitrootlogin 显示 without-password 是 prohibit-password 的别名，含义相同。通过项数随服务端 sshd 的关键字与公钥数量变化，示例是 13 项；只看失败项。

失败项对照

现象原因处理
第 2 项失败，公钥登录不通公钥未装、用户名或端口不符、密钥权限过宽先解决这一项，后面的检查都以它为前提。ssh -v 看实际尝试的身份
第 3 项失败，仍提示密码某个排序更靠前的 drop-in 设了 PasswordAuthentication yesgrep -r PasswordAuthentication /etc/ssh/sshd_config*，改掉靠前的那一行后 systemctl reload ssh
第 4 项读不到 sshd -T登录用户不是 root，且没有免密 sudo用 root 密钥登录，或给该用户配置 NOPASSWD 的只读命令
第 5 项提示「全局 ALLOW 规则覆盖」同端口还有一条不限来源的 ufw allowufw --force delete allow <端口>/tcp，保留 LIMIT 那一条
连接超时，ssh 无响应短时间内新连接过多，触发 ufw limit等 30 秒重试。规则按来源限制 6 次/30 秒
与服务器完全失联密码已关闭且密钥不可用走云控制台 VNC，执行 sudo bash bin/harden/harden.sh --uninstall

锁死之前的自救顺序

  1. 不要关闭当前已经登录的会话。当前会话不受新配置影响，可以继续修。
  2. 在另一个终端验证密钥登录：ssh -o BatchMode=yes <别名> true。
  3. 失败时在当前会话里执行 sudo bash bin/harden/harden.sh --uninstall，恢复密码登录。
  4. 修好公钥问题后重新执行加固，并再次用另一个终端验证。
会话断开策略。ClientAliveInterval 300 配 ClientAliveCountMax 2，空闲约 10 分钟断开。批量操作请放进 tmux，否则会在中途掉线。

日常核对

sshd -T | grep -iE '^(passwordauthentication|permitrootlogin|maxauthtries|maxstartups)'
ufw status numbered | grep 4061
fail2ban-client status sshd
lastb | head -20

lastb 列出失败登录；配合 fail2ban 的封禁记录可以交叉验证，确认没有持续的定向尝试。
