客户端配置

主读者：在 macOS、Linux 或 Windows 上准备免密登录的运维者。本页只做一件事：让 ssh 别名 直接进服务器，不再输密码。

一条命令完成

bash bin/harden/client.sh --host 203.0.113.10 --port 4061 --alias vps-byte --install-server

--alias 是你给这台服务器起的名字，之后用 ssh vps-byte 登录。名字由你定，本页示例用 vps-byte；不给时脚本先复用已有同地址块的名字，都没有才落到默认的 vps。

脚本做四件事，每件都幂等：

动作细节
生成或复用密钥已有 ~/.ssh/id_ed25519 就用它，没有则生成 Ed25519，不设口令
安装公钥先查服务器上是否已存在同一把公钥，避免重复追加；只追加，不改动其他行
写 ~/.ssh/config同地址同端口已有块时复用它；--alias 与块名相同但地址、端口或密钥不同时，就地重写该块并备份为 config.bak
验证用 BatchMode=yes 连一次，失败即以非零退出

生成的配置

Host vps-byte
  HostName 203.0.113.10
  Port 4061
  User root
  IdentityFile /Users/你/.ssh/id_ed25519
  IdentitiesOnly yes

Host 后面就是你的服务器名字。多台机器建议各起一个能区分用途的名字（vps-byte、vps-hk、test-box），不要都叫 vps：名字重复时后写的块会先被匹配到，改端口时容易改错机器。

IdentityFile 写的是绝对路径，脚本按本机实际 HOME 展开；手工改这段时别换成 ~，OpenSSH 展开 ~ 用的是 passwd 里的家目录，与 HOME 环境变量无关，换用户执行会指向别处。

IdentitiesOnly yes 让客户端只尝试这一把密钥。服务器 MaxAuthTries 3 时，客户端若挨个试代理里的密钥，几次就会耗尽配额。

已有配置怎么复用

之前用 ssh-copy-id、图形客户端或别的手册配过同一台服务器时，~/.ssh/config 里往往已经有一条可用记录。脚本按地址与端口找它，能复用就不新写一份：

现状脚本行为
已有块指向同一地址与端口沿用该块的名字与 IdentityFile，不新建；公钥已在服务器上时也不重复追加
要改名，地址端口不变--alias 新名字：写入新名字的块，旧块按 --prune 或提示删除
地址不变，端口变了用旧名字配 --alias 旧名字 重跑，脚本就地改写该块的 Port，并备份 config.bak
指向同一地址的块有多条先提示，是否删除由你决定；--prune 直接删掉多余的那几条
 
# 只看不写：报告目标、将沿用的名字与密钥、已有块、能否登录
bash bin/harden/client.sh --host 203.0.113.10 --port 4061 --check

# 预览要写什么，不改任何文件
bash bin/harden/client.sh --host 203.0.113.10 --port 4061 --alias vps-byte --dry-run

# 改名并清理指向同一地址的旧块
bash bin/harden/client.sh --host 203.0.113.10 --port 4061 --alias vps-byte --prune --yes
脚本只删自己识别得到的重复块（HostName 与 Port 都相同），不同地址的块一律不碰。删除前都会备份 ~/.ssh/config.bak。

分平台说明

平台OpenSSH 来源注意
macOS系统自带钥匙串可用 ssh-add --apple-use-keychain，但本方案不需要保管口令
Linux发行版自带无额外依赖
Windows 10/11系统自带 OpenSSH Client路径为 %USERPROFILE%\.ssh；脚本在 Git Bash 或 WSL 中执行

不安装第三方 SSH 客户端，也不用图形工具。WinSCP 这类图形客户端读取同一份 ~/.ssh/config 与同一把密钥即可。

密钥的几个决定

  • 算法用 Ed25519。密钥短、签名快、无参数需要挑选。
  • 不设口令。免密登录的前提是密钥无口令；密钥文件权限设为 600。需要额外保护时用系统登录密码与全盘加密，而不是给密钥加口令后再依赖 ssh-agent。
  • 一台设备一把密钥。吊销时删掉服务器上对应那一行，不影响其他设备。

手工做法

手工做完后同样建议补一条 Host 块，否则每次都要写地址与端口；已经手工配过的，直接 bash bin/harden/client.sh --host 地址 --port 端口 --check 看脚本能不能复用它。

ssh-keygen -t ed25519 -C "laptop"
ssh-copy-id -p 4061 root@203.0.113.10      # Windows 无 ssh-copy-id，用下面的写法
type %USERPROFILE%\.ssh\id_ed25519.pub | ssh -p 4061 root@203.0.113.10 "cat >> ~/.ssh/authorized_keys"
ssh -o BatchMode=yes -p 4061 root@203.0.113.10 true   # 这一步成功再继续
不要在密钥登录验证通过之前关闭密码登录。顺序颠倒会同时失去两种登录方式，此时只能走云控制台。

检查本机状态

bash bin/harden/client.sh --check
